\begin{keepsection}
\Needspace{6\baselineskip}
\section{2.1 Algorithms are finite, executable procedures}

An algorithm turns a problem into steps that a person or machine can carry out. A precise procedure also makes it possible to decide whether it finishes and what output it should produce.

\begin{keepsection}
\Needspace{14\baselineskip}
\subsection{From declarative facts to imperative steps}

\Needspace{11\baselineskip}
\textbf{Declarative knowledge} states facts. \textbf{Imperative knowledge} describes how to do something: a sequence of actions with a flow of control and a stopping condition. An algorithm is a finite, well-defined sequence of executable instructions for a class of problems or a computation.

\begin{equationcard}{Algorithm checklist}
\[ \begin{gathered} \text{input}\, \to \, \text{defined}\, \text{instructions}\, \to \, \text{output} \\ \text{finite}\, \text{text}\, \cdot \, \text{executable}\, \text{steps}\, \cdot \, \text{finite}\, \text{memory}\, \cdot \, \text{finite}\, \text{steps} \end{gathered} \]
{\small The slides call finite memory use dynamic finiteness and a finite number of steps halting. A procedure that never stops does not deliver its required result.}
\end{equationcard}

\Needspace{7\baselineskip}
The slides give a tiny example: even “1 + 2 + 3 =” is an algorithm, because it fixes the steps, their order and when you are finished.

\Needspace{12\baselineskip}
An algorithm is more specific than “find a square root”: it says how to make and check successive guesses. The procedure in the notes starts with a guess \textit{g}; if \textit{g}\textsuperscript{2} is close enough to \textit{x}, it stops. Otherwise it replaces \textit{g} with the average of \textit{g} and \textit{x}/\textit{g}.

\begin{workedbox}{Worked example \ensuremath{\cdot} follow the square-root recipe}
For \textit{x} = 16 and initial guess \textit{g} = 3, calculate two updates.

\Needspace{8\baselineskip}
\begin{enumerate}
\item First compare 3\textsuperscript{2} = 9 with 16, so continue. The next guess is (3 + 16/3)/2 \ensuremath{\approx} 4.167.
\item Now 4.167\textsuperscript{2} \ensuremath{\approx} 17.36, so update again: (4.167 + 16/4.167)/2 \ensuremath{\approx} 4.003.
\item The next estimate is about 4.000. The procedure approaches \ensuremath{\surd}16 and stops when its chosen closeness test succeeds. \hfill{\small\color{FAUblue}§2.1}
\item Sanity check: 4\textsuperscript{2} = 16, so the guesses are heading for the true root.
\end{enumerate}
\end{workedbox}

\Needspace{5\baselineskip}
\begin{notebox}\textbf{Trap:} an iteration rule is not complete until it states what counts as close enough and what happens when that test is not met.\end{notebox}

\begin{keepsection}
\Needspace{8\baselineskip}
\section{2.2 A stored-program computer executes instructions}

At bottom a computer does two things: it calculates and it remembers results, and it only knows what it is told. A stored-program computer can carry out many different procedures because its instructions are data stored in memory. The same machine follows a different algorithm when the stored program changes.

\begin{keepsection}
\Needspace{17\baselineskip}
\subsection{Instructions, control flow, and architecture}

\Needspace{14\baselineskip}
A \textbf{fixed-program computer}, such as a calculator, does one built-in job. A \textbf{stored-program computer} stores and executes instructions, so its job can change. It keeps a sequence of instructions in memory. A processor executes them using primitive operations such as arithmetic or logic, simple tests, and moving data. Tests can change which instruction runs next; execution stops when the program says it is done or reaches its stopping condition.

\begin{equationcard}{Machine-level view}
\[ \begin{gathered} \text{program}\, \text{in}\, \text{memory}\, \to \, \text{processor}\, \text{executes}\, \text{instructions}\, \to \, \text{input}\, \text{becomes}\, \text{output} \end{gathered} \]
{\small The slide's diagram: the CPU holds a control unit and a processor; the processor holds registers and combinational logic. Main memory, input and output sit outside the CPU, and instructions pass from memory to the control unit. It is a simplified model, not a particular modern computer.}
\end{equationcard}

\Needspace{10\baselineskip}
The lecture lists six abstract Turing-machine primitives: move right, move left, print a symbol, scan the current symbol, erase it, and do nothing (halt). Modern programming languages package low-level actions into more convenient operations, and you can use abstract methods to create new primitives. A language gives you primitives; expressions are legal combinations of them; expressions and computations have values and meanings. A computable procedure can be expressed in different general-purpose languages, even though syntax and tools differ.

\Needspace{11\baselineskip}
\begin{notebox}\textbf{Memory hook:} the algorithm is the recipe; the stored program is that recipe represented as instructions the machine can execute.\end{notebox}

\begin{keepsection}
\Needspace{7\baselineskip}
\section{2.3 Programs have syntax, static meaning, and behaviour}

A computer needs instructions that are legal in its language and have a defined interpretation. Separating the kinds of errors helps explain why a program can be rejected, crash, or run while still giving the wrong answer.

\begin{keepsection}
\Needspace{16\baselineskip}
\subsection{Three checks on a program expression}

\Needspace{13\baselineskip}
\textbf{Syntax} asks whether the symbols form a legal expression. \textbf{Static semantics} asks whether a syntactically legal expression is meaningful under the language's rules, such as whether the operands have compatible types. \textbf{Semantics} is the meaning associated with an expression that passes those checks.

\begin{equationcard}{Examples from the slides}
\[ \begin{gathered} "\text{hi}"5\, \to \, \text{not}\, \text{syntactically}\, \text{valid} \\ 3.2\, *\, 5\, \to \, \text{syntactically}\, \text{valid}\, \text{and}\, \text{meaningful} \\ 3\, +\, "\text{hi}"\, \to \, \text{syntactically}\, \text{valid},\, \text{but}\, {a}\, \text{static}\, \text{semantic}\, \text{error} \end{gathered} \]
{\small English shows the same split: “cat dog boy” is not syntactically valid, and “I are hungry” is valid syntax with a static semantic error. The exact type rules depend on the language.}
\end{equationcard}

\Needspace{10\baselineskip}
A syntactic error is common and easily caught. Only some languages check for static semantic errors before running, and these errors can cause unpredictable behaviour. A semantic error can be harder: the program may stop, run forever, or return an answer different from the programmer's intention. English can be ambiguous: “Flying planes can be dangerous” has two meanings. A program statement has exactly one meaning, but it may not be the one its author intended.

\Needspace{7\baselineskip}
A program can contain definitions and commands. An interpreter evaluates them in a shell, or a compiler translates the program into processor instructions. Commands may be entered directly or saved in a file for the shell to read.

\Needspace{14\baselineskip}
\begin{notebox}\textbf{Trap:} “it runs” does not mean “it is right”. A program with no syntax or static semantic errors can still give the wrong answer.\end{notebox}

\begin{keepsection}
\Needspace{6\baselineskip}
\section{2.4 Propositions turn logic into two-valued inputs}

Boolean circuits calculate with truth values. Propositional logic gives precise rules for combining statements before those rules are translated into algebra or gates.

\begin{keepsection}
\Needspace{14\baselineskip}
\subsection{Statements and connectives}

\Needspace{11\baselineskip}
A \textbf{proposition} is a statement that is either true or false. Compound propositions use \textbf{NOT}, \textbf{AND}, and \textbf{OR}. In the notes' example, the umbrella output is true when it is raining or the forecast is bad.

\begin{equationcard}{Core connectives}
\[ \begin{gathered} \neg {A}\, \text{is}\, \text{true}\, \text{exactly}\, \text{when}\, {A}\, \text{is}\, \text{false} \\ {A}\, \land \, {B}\, \text{is}\, \text{true}\, \text{exactly}\, \text{when}\, \text{both}\, {A}\, \text{and}\, {B}\, \text{are}\, \text{true} \\ {A}\, \lor \, {B}\, \text{is}\, \text{true}\, \text{when}\, \text{at}\, \text{least}\, \text{one}\, \text{of}\, {A}\, \text{or}\, {B}\, \text{is}\, \text{true} \end{gathered} \]
{\small The OR in this lecture is inclusive: it is also true when both inputs are true.}
\end{equationcard}

\Needspace{7\baselineskip}
For example, let \textit{R} mean “it is raining” and \textit{W} mean “the weather forecast is bad”. The umbrella decision is \textit{U} = \textit{W} \ensuremath{\lor} \textit{R}. If \textit{W} = 0 and \textit{R} = 1, then \textit{U} = 1.

\Needspace{6\baselineskip}
More complex decisions combine several operations. The lecture gives \textit{U} = \textit{C}' \ensuremath{\cdot} (\textit{W} + \textit{R}): take an umbrella when you are not taking the car and either the forecast is bad or it is raining. Parentheses matter because the operations have different precedence.

\item Write the umbrella rule “raining or bad forecast” with R and W.
\end{enumerate}

\begin{keepsection}
\Needspace{7\baselineskip}
\section{2.5 Boolean algebra and truth tables make the rules checkable}

Boolean algebra replaces long verbal propositions with symbols and gives every operation a precise meaning. Truth tables then provide a direct way to calculate an expression for every possible input.

\begin{keepsection}
\Needspace{14\baselineskip}
\subsection{Translate propositions into algebra}

\Needspace{11\baselineskip}
Boolean values use 1 for TRUE and 0 for FALSE. Variables stand for propositions. The supplied slides write NOT as a prime, OR as +, and AND as \ensuremath{\cdot}. Read the notation carefully: here + is logical OR, not ordinary arithmetic addition.

\begin{equationcard}{Notation and precedence}
\[ \begin{gathered} {A}'\, =\, \text{NOT}\, {A} \\ {A}\, \cdot \, {B}\, =\, {A}\, \text{AND}\, {B} \\ {A}\, +\, {B}\, =\, {A}\, \text{OR}\, {B} \\ \text{NOT}\, \text{first}\, \cdot \, \text{AND}\, \text{next}\, \cdot \, \text{OR}\, \text{last} \end{gathered} \]
{\small Use parentheses to make grouping explicit. For example, C' \ensuremath{\cdot} (W + R) is different from C' \ensuremath{\cdot} W + R. In C, logical operators are \&\&, ||, !; bitwise operators are \&, |, ~ (the slide labels these “Binary”; see Slips in the notes).}
\end{equationcard}
\end{keepsection}

\begin{keepsection}
\Needspace{15\baselineskip}
\subsection{Enumerate every input}

\Needspace{12\baselineskip}
A truth table lists an expression's output for every assignment of its input variables. With \textit{n} Boolean variables there are 2\textsuperscript{n} assignments. Two expressions are equivalent when their output columns match in every row.

\Needspace{10\baselineskip}
\begin{center}\small\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}\toprule
\textbf{A} & \textbf{B} & \textbf{A \ensuremath{\land} B} & \textbf{A \ensuremath{\lor} B} & \textbf{\ensuremath{\neg}A} \\ \midrule
0 & 0 & 0 & 0 & 1 \\
0 & 1 & 0 & 1 & 1 \\
1 & 0 & 0 & 1 & 0 \\
1 & 1 & 1 & 1 & 0 \\
\bottomrule\end{tabularx}\end{center}

\begin{workedbox}{Worked example \ensuremath{\cdot} the umbrella truth table}
Build the table for \textit{U} = \textit{C}' \ensuremath{\cdot} (\textit{W} + \textit{R}) with partial results.

\Needspace{5\baselineskip}
\begin{enumerate}
\item Three variables give 2\textsuperscript{3} = 8 rows. List (R,W,C) from 000 to 111.
\item Name the partial results: X1 = R + W and X2 = C'.
\item Fill X1, then X2, then U = X1 \ensuremath{\cdot} X2.
\end{enumerate}

\Needspace{10\baselineskip}
\begin{center}\small\begin{tabularx}{\linewidth}{>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X>{\raggedright\arraybackslash}X}\toprule
\textbf{R} & \textbf{W} & \textbf{C} & \textbf{X1 = R + W} & \textbf{X2 = C'} & \textbf{U = X1 \ensuremath{\cdot} X2} \\ \midrule

\end{workedbox}
\end{keepsection}

\begin{keepsection}
\Needspace{11\baselineskip}
\subsection{Implication (beyond the notes)}

\Needspace{8\baselineskip}
Implication is not in these slides; the “=\ensuremath{>}” on slide 24 only means “we could write”. Take this truth table as its definition: A \ensuremath{\Rightarrow} B is false only for A = 1, B = 0, so its column for (A,B) = 00, 01, 10, 11 is 1, 1, 0, 1. Evaluating A' + B gives 1, 1, 0, 1 as well, so the two are equivalent.

\Needspace{5\baselineskip}
\begin{notebox}\textbf{Trap:} three input variables require eight rows, not six. List all assignments before calculating an output column. And + means OR here, so 1 + 1 = 1.\end{notebox}

\begin{keepsection}
\Needspace{6\baselineskip}
\section{2.6 Boolean laws simplify expressions}

Boolean laws let you transform an expression while preserving its output. Each identity can be checked with a truth table, and the same law can simplify the design of a circuit.

\begin{keepsection}
\Needspace{10\baselineskip}
\subsection{Core identities}

\begin{equationcard}{Negation, identity, and idempotence}
\[ \begin{gathered} ({A}')'\, =\, {A} \\ {A}\, \cdot \, {A}'\, =\, 0 \\ {A}\, +\, {A}'\, =\, 1 \\ {A}\, \cdot \, {A}\, =\, {A} \\ {A}\, +\, {A}\, =\, {A} \\ {A}\, \cdot \, 0\, =\, 0 \\ {A}\, \cdot \, 1\, =\, {A} \\ {A}\, +\, 0\, =\, {A} \\ {A}\, +\, 1\, =\, 1 \end{gathered} \]
{\small The slides use \ensuremath{\cdot} for AND and + for OR. A and B may themselves be compound Boolean expressions. (A')' = A is listed under “Negation”, and the NAND slides call it the Involution law.}
\end{equationcard}

\begin{equationcard}{Commutative, associative, and distributive}
\[ \begin{gathered} {A}\, \cdot \, {B}\, =\, {B}\, \cdot \, {A} \\ {A}\, +\, {B}\, =\, {B}\, +\, {A} \\ ({A}\, \cdot \, {B})\, \cdot \, {C}\, =\, {A}\, \cdot \, ({B}\, \cdot \, {C}) \\ ({A}\, +\, {B})\, +\, {C}\, =\, {A}\, +\, ({B}\, +\, {C}) \\ {A}\, \cdot \, ({B}\, +\, {C})\, =\, {A}\, \cdot \, {B}\, +\, {A}\, \cdot \, {C} \\ {A}\, +\, ({B}\, \cdot \, {C})\, =\, ({A}\, +\, {B})\, \cdot \, ({A}\, +\, {C}) \end{gathered} \]
{\small Parentheses keep the grouping visible. The two distributive laws mirror each other with AND and OR exchanged.}
\end{equationcard}
\end{keepsection}

\begin{keepsection}
\Needspace{12\baselineskip}
\subsection{De Morgan's rules}

\Needspace{9\baselineskip}
Negating a compound expression changes its operation and negates each input: NOT of an OR becomes an AND of the negations, and NOT of an AND becomes an OR of the negations.

\begin{equationcard}{De Morgan's laws}
\[ \begin{gathered} ({A}\, +\, {B})'\, =\, {A}'\, \cdot \, {B}' \\ ({A}\, \cdot \, {B})'\, =\, {A}'\, +\, {B}' \\ ({A}\, +\, {B}\, +\, {C}\, +\, …)'\, =\, {A}'\, \cdot \, {B}'\, \cdot \, {C}'\, \cdot \, … \\ ({A}\, \cdot \, {B}\, \cdot \, {C}\, \cdot \, …)'\, =\, {A}'\, +\, {B}'\, +\, {C}'\, +\, … \end{gathered} \]
{\small The rules hold for any number of inputs.}
\end{equationcard}

\begin{workedbox}{Worked example \ensuremath{\cdot} simplify a negated expression}
Rewrite (A + B)' using De Morgan's law, then evaluate it when A = 0 and B = 1.

\Needspace{5\baselineskip}
\begin{enumerate}
\item Apply (A + B)' = A' \ensuremath{\cdot} B'.
\item Substitute the inputs: 1 \ensuremath{\cdot} 0 = 0.
\item The original expression is false because at least one input to the OR was true. \hfill{\small\color{FAUblue}§2.6}
\end{enumerate}
\end{workedbox}

\Needspace{4\baselineskip}
\begin{notebox}\textbf{Trap:} De Morgan swaps the operator as well as priming each input. (A + B)' is not A' + B'.\end{notebox}

A gate is a circuit block whose output follows a Boolean rule. Algebra connects a circuit diagram to its expression and makes it possible to build several operations from a universal gate.

\begin{keepsection}

\end{equationcard}

\begin{keepsection}
\Needspace{14\baselineskip}
\subsection{NAND is a universal gate}

\Needspace{11\baselineskip}
The lecture calls a set of functions complete when combinations of those functions can generate any Boolean function. NAND alone is complete, so it is also called a universal gate. NAND and NOR are the commonly used building blocks because they are easy to construct from transistors.

\begin{equationcard}{Building gates from NAND}
\[ \begin{gathered} \text{NOT}:\, ({A}\, \cdot \, {A})'\, =\, {A}'\, (\text{idempotent}\, \text{law}) \\ \text{AND}:\, (({A}\, \cdot \, {B})')'\, =\, {A}\, \cdot \, {B}\, (\text{involution}\, \text{law}) \\ \text{OR}:\, {A}\, +\, {B}\, =\, ({A}'\, \cdot \, {B}')'\, (\text{De}\, \text{Morgan}) \\ \text{NOR}:\, \text{invert}\, \text{the}\, \text{OR}\, \text{output} \end{gathered} \]
{\small NOT takes one NAND with tied inputs, AND takes two, and OR takes three: one to invert each input and one to combine them.}
\end{equationcard}

\begin{workedbox}{Worked example \ensuremath{\cdot} translate a two-stage NAND circuit}

\Needspace{7\baselineskip}

\begin{keepsection}

\begin{keepsection}\subsection{Explain it}

\Needspace{24\baselineskip}
\begin{enumerate}
\item Without a stopping condition, the procedure may keep repeating and never return an answer. Halting is part of the definition, so a recipe that may run forever is not an algorithm for that input. The stop test is what turns repetition into a result. \hfill{\small\color{FAUblue}§2.1}
\item The stored instructions can change while the hardware remains the same; the machine follows the program it is given. A calculator cannot do this, because its job is built in. \hfill{\small\color{FAUblue}§2.2}
\item The second expression is syntactically valid but has a static semantic problem: the operands cannot be combined meaningfully under the illustrated rules. Invalid syntax, such as "hi"5, is not a legal expression at all. The first problem concerns meaning, the second form. \hfill{\small\color{FAUblue}§2.3}
\item Each variable has two possible values, so all combinations number 2 multiplied by itself n times. Every extra variable doubles the rows, because each old row appears once with 0 and once with 1. \hfill{\small\color{FAUblue}§2.5}
\item NOT, AND, and OR have a precedence order; without parentheses the expression groups differently and can produce a different output. C' \ensuremath{\cdot} W + R means (C' \ensuremath{\cdot} W) + R, so R = 1 gives 1 even when C = 1. With the parentheses the same input gives 0. \hfill{\small\color{FAUblue}§2.5}
\item Any Boolean function can be assembled using NAND gates alone. NOT, AND and OR can each be built from NAND, and those three express any truth table. That is the slides' meaning of a complete set. \hfill{\small\color{FAUblue}§2.7}
\item A truth table describes stable input-output values, while real gates have switching delay and saturation limits. It says where the output ends up, not when it gets there. Two circuits with the same table may differ in timing. \hfill{\small\color{FAUblue}§2.8}
\end{enumerate}

\end{keepsection}
\begin{keepsection}\subsection{Mixed practice}

\begin{enumerate}
\item A sequence of simple steps, control flow that determines when each step runs, and a way to know when to stop. \hfill{\small\color{FAUblue}§2.1}
\item A \ensuremath{\land} B=0, A \ensuremath{\lor} B=1, and \ensuremath{\neg}A=0. \hfill{\small\color{FAUblue}§2.4}
\item A stored-program computer. \hfill{\small\color{FAUblue}§2.2}
\item 2\textsuperscript{4}=16 rows. \hfill{\small\color{FAUblue}§2.5}
\item It is syntactically valid but has a static semantic error in the slide's example. \hfill{\small\color{FAUblue}§2.3}
\item A' + B'. \hfill{\small\color{FAUblue}§2.6}
\item Both are 0. Their matching outputs for this row are consistent with the equivalence; check all four rows to prove it. \hfill{\small\color{FAUblue}§2.5}
\item (2 + 9/2)/2 = 6.5/2 = 3.25. It is above \ensuremath{\surd}9 = 3 and closer than 2 was. \hfill{\small\color{FAUblue}§2.1}
\item (A + B + C)' = A' \ensuremath{\cdot} B' \ensuremath{\cdot} C'. \hfill{\small\color{FAUblue}§2.6}
\item The Boolean model gives stable outputs for inputs; a physical circuit also takes time to switch and has limits such as saturation. \hfill{\small\color{FAUblue}§2.8}
\item NOT first gives A'=1; AND next gives B\ensuremath{\cdot}C=1; OR last gives 1+1=1. \hfill{\small\color{FAUblue}§2.5}
\item It may crash, run forever, or return an answer different from the programmer's intention. \hfill{\small\color{FAUblue}§2.3}
\item XOR=0 and XNOR=1 because the inputs agree. \hfill{\small\color{FAUblue}§2.7}
\item A\ensuremath{\cdot}A=A, so A\ensuremath{\cdot}A+A=A+A=A. \hfill{\small\color{FAUblue}§2.6}
\item \&\& is logical AND; \& is bitwise AND. \hfill{\small\color{FAUblue}§2.5}
\item X=((A\ensuremath{\cdot}B)'\ensuremath{\cdot}C)'=((A\ensuremath{\cdot}B)')'+C'=A\ensuremath{\cdot}B+C'. \hfill{\small\color{FAUblue}§2.7}
\item Replace g by the average of g and x/g, then test the new guess again. \hfill{\small\color{FAUblue}§2.1}
\item Let Y=A+B. Then Y'\ensuremath{\cdot}Y=0 by the complement law. \hfill{\small\color{FAUblue}§2.6}
\item I=(0\ensuremath{\cdot}1)'=1, then X=(1\ensuremath{\cdot}0)'=1. The simplified form agrees: 0\ensuremath{\cdot}1+1=1. \hfill{\small\color{FAUblue}§2.7}
\item There are 8 truth-table rows and two possible output choices per row, so 2\textsuperscript{8}=256 functions. \hfill{\small\color{FAUblue}§2.5}
\item A + B=((A\ensuremath{\cdot}A)'\ensuremath{\cdot}(B\ensuremath{\cdot}B)')'. De Morgan gives (A'\ensuremath{\cdot}B')'=A+B, and each (X\ensuremath{\cdot}X)' is a NOT by the idempotent law. \hfill{\small\color{FAUblue}§2.7}
\item Run different programs on the same hardware, because its instructions are stored and can change. A calculator does one built-in job. \hfill{\small\color{FAUblue}§2.2}
\item "hi"5 is a syntax error; 3 + "hi" is a static semantic error; 3.2 * 5 is valid. \hfill{\small\color{FAUblue}§2.3}
\item W must be 0 and C or R must be 1: (0,1,0), (1,0,0), (1,1,0). \hfill{\small\color{FAUblue}§2.5}
\item C'=0, so C'\ensuremath{\cdot}W+R=0+1=1, but C'\ensuremath{\cdot}(W+R)=0\ensuremath{\cdot}1=0. The parentheses change the result. \hfill{\small\color{FAUblue}§2.5}
\end{enumerate}

\end{keepsection}
