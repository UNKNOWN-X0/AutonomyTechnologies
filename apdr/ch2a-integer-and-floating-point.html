3.1 Number systems and positional notation

A numeral is a compact way to write a sum of place values. Binary, octal, decimal, and hexadecimal use the same positional rule with different bases.

Expand and convert

In base b, each digit di contributes dibi, where the rightmost digit has i=0. Binary digits are 0 or 1. Decimal-to-binary repeated division records remainders; read them from last to first.

Positional value(dk…d1d0)b = Σ dibi(1100010)2 = 1·26 + 1·25 + 1·21 = 98The worked binary number is 98 in decimal. Subscripts identify the base.

Worked conversion · decimal to binary

Convert 45 to binary by repeated division.

  1. 45 ÷ 2 gives quotient 22, remainder 1.
  2. 22 ÷ 2 gives quotient 11, remainder 0; then 11 gives 5 remainder 1.
  3. Continue: 5 gives 2 remainder 1; 2 gives 1 remainder 0; 1 gives 0 remainder 1.
  4. Read remainders upward: 1011012. Check: 32+8+4+1=45. §3.1

Octal and hexadecimal

Because 8=23, each octal digit corresponds to three binary digits. Because 16=24, each hexadecimal digit corresponds to four bits. Group binary digits from the right and pad the leftmost group with zeroes if needed. In hexadecimal, A–F mean 10–15.

Compact binary groups101012 = 010 101 = 258100101002 = 1001 0100 = 94161 byte = 8 bits = 2 hexadecimal digitsThe lecture uses 16-bit words and 32-bit long words as examples; the sizes named by these terms can depend on a computer architecture.

Trap: do not read a binary string as an ordinary decimal integer. Attach its base, expand it, and only then compare values.

3.2 Integer representations

A computer stores a fixed number of bits, not a plus or minus sign unless the encoding defines one. The same pattern can mean different values under different encodings.

Unsigned and signed ranges

An unsigned n-bit pattern represents 0 through 2n−1. Signed encodings trade positive range for negative values. The source compares sign-and-magnitude, one’s complement, two’s complement, excess (biased) notation, and binary-coded decimal (BCD).

Ranges for n bitsUnsigned: 0 … 2n−1Sign and magnitude: −(2n−1−1) … +(2n−1−1)One’s complement: −(2n−1−1) … +(2n−1−1)Two’s complement: −2n−1 … 2n−1−1Sign-and-magnitude and one’s complement have two zero encodings. Two’s complement has one zero and one extra negative value.

Worked comparison · decode 1111 in four encodings

  1. Unsigned: 15.
  2. Sign-and-magnitude: sign bit 1 and magnitude 111, so −7.
  3. One’s complement: invert to 0000, so −0, which equals zero but has a distinct pattern.
  4. Two’s complement: the unsigned value 15 represents 15−16=−1. §3.2

Two’s complement and bias

To form −x in n-bit two’s complement, invert all n bits of x and add 1; discard a carry beyond the width. The minimum value −2n−1 is the exception: its positive counterpart is outside the signed range, so fixed-width negation leaves the same pattern and overflows. Equivalently, interpret a pattern with top bit 1 by subtracting 2n from its unsigned value. In excess-B notation, actual value = stored unsigned value − B. The lecture’s three-bit excess-4 example therefore maps 000 to −4 and 111 to 3.

Decode rulesTwo’s-complement value = unsigned(pattern) − 2n when the top bit is 1Negate x: invert n bits, then add 1Excess-B value = stored value − BKeep the width fixed throughout. The same bit pattern has no signed meaning until an encoding is specified.

BCD stores decimal digits separately

In four-bit BCD, each decimal digit has its own four-bit code. For example, decimal 59 is 0101 1001 in BCD, while the ordinary binary value 59 is 00111011. BCD uses more bits but keeps each decimal digit directly readable.

Trap: do not convert all BCD bits as one binary number. Decode each four-bit group as a decimal digit.

3.3 Character data

Numbers are not the only data stored as bits. A character encoding assigns numeric codes to letters, digits, punctuation, and control characters.

ASCII and Unicode

ASCII uses seven bits, giving 128 code values. The lecture describes eight-bit extensions that use the additional 128 patterns, but those upper values depend on the particular extension. Unicode assigns code points to characters across many writing systems; its first 128 code points match ASCII. A code point and its byte encoding are related but are not the same concept.

Character-code facts7-bit ASCII: 27 = 128 code valuesASCII code points: 0 … 127The first 128 Unicode code points correspond to ASCII. Byte encodings represent code points as bytes by their own rules.

Worked encoding · read a short ASCII string

The lecture’s example encodes “Fred” in hexadecimal as 46 72 65 64.

  1. Split the bytes: 46, 72, 65, 64.
  2. Read each as a hexadecimal ASCII code: 46 is F, 72 is r, 65 is e, and 64 is d.
  3. The four codes decode to “Fred”. §3.3

Trap: an encoding is a mapping, not a property of the bit pattern by itself. Identify the character set and any byte encoding before decoding text.

3.4 Unsigned binary arithmetic

Binary arithmetic follows the same place-value logic as decimal arithmetic. Carries and borrows move between columns, while the fixed bit width limits which values can be stored.

Add and subtract

Add each column and carry 1 when a column totals 2. For subtraction, borrow from a higher column when the current minuend bit is too small; a borrowed binary 1 is worth 2 in the current column. Subtraction can also be checked by adding the difference to the subtrahend.

Worked addition · include the carry

Add 1110112 and 1010102.

  1. From right to left: 1+0=1.
  2. 1+1=10, so write 0 and carry 1. Continue each column with its carry.
  3. The result is 11001012. Check: 59+42=101, and 11001012=101. §3.4

Multiply and divide

Binary multiplication uses partial products, like decimal long multiplication, but each multiplier bit is only 0 or 1. Binary division uses quotient and remainder. For divisor d≠0, dividend = quotient×divisor + remainder, where 0≤remainder<divisor.

Division checkdividend = quotient × divisor + remainder0 ≤ remainder < divisorSubstitute the quotient, divisor, and remainder to check a division result.

Memory hook: in binary addition, 1+1 writes 0 and carries 1. In subtraction, a borrow makes the current column worth 2 before subtracting.

3.5 Two’s-complement arithmetic and overflow

Two’s complement lets the same adder perform signed addition and subtraction. Correct bit operations still need a range check: a fixed-width result can wrap to a pattern with a different signed value.

Addition, subtraction, and overflow

Add the bit patterns and discard any carry beyond the most significant bit. For subtraction, negate the subtrahend and add it to the minuend. Signed overflow occurs when the exact mathematical result lies outside the representation’s range. For addition, it occurs when two operands with the same sign produce a result with the opposite sign; operands of unlike signs cannot overflow.

n-bit two’s-complement checksRange: −2n−1 … 2n−1−1A − B = A + (two’s-complement negation of B)Same-sign addition with opposite-sign result ⇒ overflowDiscarding carry-out is part of fixed-width addition. Carry-out alone does not signal signed overflow.

Worked example · detect overflow

Use four-bit two’s complement to calculate −7+(−6).

  1. Encode −7 as 1001 and −6 as 1010.
  2. Add: 1001+1010=1 0011. Discard the carry-out, leaving 0011.
  3. The stored result 0011 is +3, but the exact sum is −13, outside the four-bit range −8…+7. Both inputs were negative and the result is positive, so overflow occurred. §3.5

Multiplication and division

The lecture notes that ordinary unsigned multiplication cannot simply be applied to signed two’s-complement patterns and read at the original width. A full product may require up to twice as many bits as the operands; retain a sufficient width and interpret the result consistently. For a simple signed multiplication, multiply magnitudes and make the result negative exactly when the operand signs differ, then check the available width. The supplied slides introduce this idea but do not give a complete signed division algorithm.

Sign check: do not treat discarded carry as overflow. Decode the fixed-width result and compare it with the exact mathematical result and allowed range.

4.1 The floating-point model

A fixed number of bits cannot represent every real number.

Floating point uses a sign, a significand, and an exponent to cover very large and very small magnitudes.

Range and precision

For base β, a normalised number has the form sign × significand × βexponent.

The exponent controls scale and therefore the approximate range.

The number of significand bits controls precision, or how finely nearby values can be distinguished.

Floating-point values are finite in number, and their spacing changes with magnitude.

Scientific notation modelx = s × M × βEs is the sign, M is the significand, β is the base or radix, and E is the exponent. In binary floating point, β=2.

Worked example · normalise a decimal value

Write 343000 × 10−4 in normalised decimal form with 1≤M<10.

  1. Move the decimal point in 343000 five places left to make 3.43.
  2. Increase the exponent by five to preserve the value: 3.43 × 101.
  3. Check: 343000 × 10−4=34.3, and 3.43 × 101=34.3. §4.1

Trap: moving the radix point changes the exponent in the opposite direction if the represented value is to stay the same.

4.2 Binary fractions

Binary fractional place values explain both conversion and approximation.

The first bit after the binary point has weight 2−1.

Each following bit has half the previous weight.

Convert binary fractions to decimal

Binary fractional place values0.b1b2…bk = b12−1 + b22−2 + … + bk2−kEach bi is 0 or 1. A leading integer part is evaluated with non-negative powers of 2.

Worked conversion · binary fraction to decimal

Convert 0.011012 to decimal.

  1. Use the five place values: 1/2, 1/4, 1/8, 1/16, and 1/32.
  2. Keep the places where the bit is 1: 1/4 + 1/8 + 1/32.
  3. Add: 0.25+0.125+0.03125=0.40625. §4.2

Convert decimal fractions to binary

Repeatedly multiply the fractional part by 2.

At each step, the integer part is the next binary digit, and the new fractional part is carried into the next step.

Worked conversion · terminating binary fraction

Convert 0.6875 to binary.

  1. 0.6875×2=1.375, so the first bit is 1; carry 0.375.
  2. 0.375×2=0.75, so the next bit is 0; carry 0.75.
  3. 0.75×2=1.5, so the next bit is 1; carry 0.5.
  4. 0.5×2=1.0, so the next bit is 1; the fraction is now zero.
  5. Therefore 0.6875=0.10112. Check: 1/2+1/8+1/16=0.6875. §4.2

Some fractions, such as 0.1 in decimal, repeat in binary.

A finite significand stores only an approximation of a repeating expansion.

Trap: a decimal fraction that looks short is not necessarily exact in binary.

4.3 Floating-point arithmetic and error

The exponent and significand must be managed during each operation.

After the exact operation, the result may need normalisation and rounding to fit the available precision.

Multiplication

Multiply normalised values(M1 × βE1)(M2 × βE2) = (M1M2) × βE1+E2Multiply the significands and add the exponents. Then normalise and round if needed.

Worked multiplication · normalise the result

Calculate (2.6×103)(5.4×10−2).

  1. Multiply significands: 2.6×5.4=14.04.
  2. Add exponents: 3+(−2)=1, giving 14.04×101.
  3. Normalise: 1.404×102=140.4. §4.3

Addition

Before adding, express both numbers with the same exponent.

Shift the significand of the value with the smaller exponent to the right by the exponent difference.

This alignment can discard low-order digits before the addition is even performed.

Worked addition · align exponents

Use two significant decimal digits to add 4.5×103 and 6.7×102.

  1. Rewrite the second value at exponent 3: 6.7×102=0.67×103.
  2. Add significands: (4.5+0.67)×103=5.17×103.
  3. Round to two significant digits: 5.2×103. The exact sum is 5170, while this two-digit result is 5200. §4.3

Rounding, overflow, and comparison

Truncation drops extra digits and tends to bias results in one direction.

Rounding chooses a nearby representable value and usually gives a better approximation.

Exponent overflow occurs when the result is too large for the format.

Exponent underflow occurs when the result is too small for the normalised range.

The slides describe infinity or an exception for overflow, and zero or an exception for underflow in their simplified model.

IEEE formats also provide subnormal numbers near zero.

For approximate comparisons, choose a tolerance ε that fits the scale and precision of the problem.

Absolute tolerance exampleTreat a as close to b when |a−b|<εFor b=1 and ε=0.000005: 0.999995<a<1.000005A fixed absolute tolerance may be unsuitable when magnitudes vary greatly. The slides also introduce relative closeness.

Sign check: estimate the order of magnitude before accepting a rounded result.

4.4 IEEE 754 binary formats

A shared format defines how floating-point fields are stored and how arithmetic behaves.

The slides introduce IEEE 754 as a widely adopted standard for predictable binary floating-point arithmetic.

Single and double precision

For a normalised binary value, the leading significand bit is 1 and is omitted from the stored fraction field.

The exponent field stores a biased exponent rather than a two’s-complement exponent.

Normalised value rulevalue = (−1)S × 1.F × 2E−biasSingle bias = 127; double bias = 1023S is the sign bit, E is the unsigned exponent field, and F is the stored fraction interpreted after the binary point. This rule is for normalised values.

Convert decimal to single precision

Worked conversion · 42.6875

  1. Convert to binary: 42.6875=101010.10112.
  2. Normalise: 1.010101011×25, so the sign bit is 0.
  3. Store the fraction after the hidden leading 1: 01010101100000000000000.
  4. Bias the exponent: 5+127=132=100001002.
  5. The fields are 0 | 10000100 | 01010101100000000000000, or hexadecimal 422A C000. §4.4

Decode single precision

Worked decoding · BEC0 0000

  1. The sign bit is 1, so the value is negative.
  2. The exponent field is 011111012=125; subtract the bias: 125−127=−2.
  3. Restore the hidden bit: 1.1000…2=1.5.
  4. Scale: 1.5×2−2=0.375. Apply the sign: −0.375. §4.4

Trap: restore the hidden leading 1 when decoding a normalised value, but do not apply that rule to a subnormal value.

4.5 Zero, subnormal numbers, infinity, and NaN

Reserved exponent patterns extend useful behaviour beyond normalised values.

In single precision, exponent field zero and exponent field all ones have special interpretations.

For a subnormal single-precision number, the leading bit is 0 and the effective exponent is −126.

Subnormal values provide a gradual step from the smallest normalised values toward zero.

Infinity represents overflow results and some divisions by zero.

Operations on infinity and NaN follow format rules, not ordinary real-number algebra in every case.

Numerical stability and cancellation

Cancellation occurs when subtracting close stored values. The subtraction may itself be exact, yet earlier rounding in the operands can dominate the small difference. A stable method avoids needlessly creating that sensitive subtraction.

Machine epsilon and relative error

Machine epsilon is the gap from 1 to the next larger representable value. For radix β and p significant digits, εmach=β1−p. Here p counts the full significand digits, including the hidden leading bit in a normalised IEEE value.

Binary machine epsilonSingle precision: p=24, εmach=2−23≈1.19×10−7Double precision: p=53, εmach=2−52≈2.22×10−16Under round-to-nearest, the unit roundoff u is εmach/2 for normal results.
Relative rounding modelfl(x)=x(1+δ), with |δ|≤uFor finite non-zero normal results, round-to-nearest, and no overflow. Relative error is measured against |x|, so the same absolute error matters more when the true answer is small.

Worked example · cancellation

Suppose five significant decimal digits store x=0.123456789 as 0.12346 and y=0.123451234 as 0.12345.

  1. The exact difference is 0.000005555.
  2. The stored difference is 0.00001.
  3. The stored difference is about 1.80 times the exact difference, so its relative error is about 80.0%. The subtraction exposed input rounding error. §4.5

Sterbenz lemma

If x and y are positive finite floating-point values in the same radix and precision, and y/2≤x≤2y, then x−y is exactly representable when gradual underflow is supported. For example, 1.5 and 1.0 meet the condition, and their difference 0.5 is exact. This does not undo rounding that happened while x or y was computed; cancellation can expose that earlier error.

Stable quadratic roots

For ax²+bx+c=0, require a≠0 and D=b²−4ac≥0. The usual formula can subtract nearly equal quantities for one root. For D>0, choose the branch that adds magnitudes: if b≥0, set q=−½(b+√D); if b<0, set q=−½(b−√D). Then the roots are q/a and c/q. This branch also handles b=0. For D=0, use the repeated root −b/(2a), since q may be zero. These steps avoid cancellation while respecting the degenerate cases.

Trap: mathematical equivalence does not guarantee equal numerical accuracy. Look for subtraction of nearly equal values and avoid rounding intermediate results unnecessarily.

Source qualification: the lecture’s performance statements about subnormals and its description of C signed-char conversion depend on implementation or execution mode. Follow the language and platform rules for a specific system.

Fused multiply-add

A fused multiply-add evaluates a×b+c with one final rounding. Separate multiplication and addition can round the product first, then round again after addition. FMA can therefore preserve more information; its speed benefit depends on hardware.

Fused versus separate roundingFMA(a,b,c)=round(a×b+c)Separate: round(round(a×b)+c)The fused operation avoids the intermediate rounding step.

Explain it

Answer each why or when aloud before opening the model response.

  1. Why does the rightmost binary digit have weight 1?
  2. Why are octal and hexadecimal convenient ways to write binary?
  3. Why do sign-and-magnitude and one’s complement have two zero patterns?
  4. Why does two’s complement have one extra negative value?
  5. When is carry-out discarded, and why is that not enough to detect signed overflow?
  6. Why can BCD be easier for decimal display but less space-efficient?
  7. Why does increasing the exponent change range more than precision?
  8. Why can two nearby real values have different spacing when stored at different magnitudes?
  9. Why does 0.1 decimal not have a finite binary fraction?
  10. Why must exponents be aligned before adding two floating-point values?
  11. Why can rounding during addition lose a small addend?
  12. Why is the leading 1 omitted for normalised binary significands?
  13. When would a subnormal number be used?
  14. Why should an approximate comparison use a tolerance chosen for the problem?
  15. Why is machine epsilon a relative-precision scale rather than one fixed absolute error for every number?
  16. When can Sterbenz’s lemma say the subtraction itself is exact, and what error can still remain?
Show model explanations
  1. The rightmost place is position zero, and any base raised to zero is 1. Its bit contributes either zero or one to the value.
  2. Each octal digit maps to exactly three bits and each hexadecimal digit to four. Grouping bits preserves their value while shortening the written form.
  3. Both encodings use a sign bit and a separate magnitude/complement pattern for zero. That creates distinct positive-zero and negative-zero bit patterns.
  4. With n bits, one pattern is used for zero and the remaining patterns cannot be divided evenly into equal positive and negative ranges. Two’s complement assigns the extra pattern to the negative side.
  5. Fixed-width addition retains only n result bits, so carry beyond the word is discarded. Signed overflow depends on the signs of the inputs and result, not on that discarded bit.
  6. Each four-bit BCD group can be read as one decimal digit, but four bits are used per decimal digit even when ordinary binary could represent the whole number with fewer bits.
  7. The exponent scales a significand by powers of the base, expanding which magnitudes can be represented. Precision depends chiefly on how many significand bits distinguish values at a given scale.
  8. At a larger exponent, the same significand step is multiplied by a larger power of 2. Therefore adjacent representable values are farther apart.
  9. A finite binary fraction has a denominator that is a power of 2 after reduction. One tenth has a factor of 5 in its denominator, so its binary expansion repeats.
  10. Only values with the same exponent have significands describing the same scale. Alignment expresses both at a shared scale before combining them.
  11. Alignment shifts the smaller significand to the right. If the exponent difference is large, its significant bits may fall beyond the available precision.
  12. Every normalised binary number begins with 1 before the point, so the format can infer that bit and use its storage for another fraction bit.
  13. A subnormal represents a non-zero value smaller than the minimum normalised magnitude, close to zero.
  14. Absolute or relative error that is acceptable depends on the scale and purpose of the calculation. One fixed tolerance may be too strict for large values or too loose for small ones.
  15. Spacing scales with the exponent, so a fixed absolute difference is a different fraction of values at different magnitudes. Machine epsilon measures spacing near 1; the relative rounding model expresses error as a fraction of the input magnitude.
  16. For positive floating-point x and y with y/2≤x≤2y, their difference is exactly representable under the format assumptions. Any rounding that already changed x or y can still affect the difference.

Do not generalise this example as signed integer overflow being defined wraparound. See clauses 6.3.1.1 and 6.3.1.3 of the WG14 C standard draft N1570.
