3.1 Number systems and positional notation

A numeral is a compact way to write a sum of place values. Binary, octal, decimal, and hexadecimal use the same positional rule with different bases.

Expand and convert

In base b, each digit di contributes dibi, where the rightmost digit has i=0. Binary digits are 0 or 1. Decimal-to-binary repeated division records remainders; read them from last to first.

Positional value(dk…d1d0)b = ∑i=0k dibi(1100010)2 = 1·26 + 1·25 + 1·21 = 98The worked binary number is 98 in decimal. Subscripts identify the base.

Worked conversion · decimal to binary

Convert 45 to binary by repeated division.

  1. 45 ÷ 2 gives quotient 22, remainder 1.
  2. 22 ÷ 2 gives quotient 11, remainder 0; then 11 gives 5 remainder 1.
  3. Continue: 5 gives 2 remainder 1; 2 gives 1 remainder 0; 1 gives 0 remainder 1.
  4. Read remainders upward: 1011012. Check: 32+8+4+1=45. §3.1

Octal and hexadecimal

Because 8=23, each octal digit corresponds to three binary digits. Because 16=24, each hexadecimal digit corresponds to four bits. Group binary digits from the right and pad the leftmost group with zeroes if needed. In hexadecimal, A–F mean 10–15.

Compact binary groups101012 = 010 101 = 258100101002 = 1001 0100 = 94161 byte = 8 bits = 2 hexadecimal digitsThe lecture uses 16-bit words and 32-bit long words as examples; the sizes named by these terms can depend on a computer architecture.

Worked conversion · hexadecimal to binary and decimal

Convert 2F16.

  1. Replace each digit by four bits: 2 is 0010 and F (15) is 1111, so 2F16=0010 11112.
  2. Expand by base 16: 2×16+15=47.
  3. Check by the bits: 32+8+4+2+1=47. §3.1

Trap: do not read a binary string as an ordinary decimal integer. Attach its base, expand it, and only then compare values.

3.2 Integer representations

A computer stores a fixed number of bits, not a plus or minus sign unless the encoding defines one. The same pattern can mean different values under different encodings.

Unsigned and signed ranges

An unsigned n-bit pattern represents 0 through 2n−1. Signed encodings trade positive range for negative values. The source compares sign-and-magnitude, one’s complement, two’s complement, excess (biased) notation, and binary-coded decimal (BCD). The lecture judges a signed encoding by four wishes: one zero, a balanced range, simple fast addition hardware, and no gaps in the number line.

Ranges for n bitsUnsigned: 0 … 2n−1Sign and magnitude: −(2n−1−1) … +(2n−1−1)One’s complement: −(2n−1−1) … +(2n−1−1)Two’s complement: −2n−1 … 2n−1−1Sign-and-magnitude and one’s complement have two zero encodings. Two’s complement has one zero and one extra negative value.

Worked comparison · decode 1111 in four encodings

  1. Unsigned: 15.
  2. Sign-and-magnitude: sign bit 1 and magnitude 111, so −7.
  3. One’s complement: invert to 0000, so −0, which equals zero but has a distinct pattern.
  4. Two’s complement: the unsigned value 15 represents 15−16=−1. §3.2

Why the older encodings lost

Sign-and-magnitude has two zeros, and its adder must compare signs and then choose whether to add or subtract magnitudes. One’s complement still has two zeros, and its addition needs an end-around carry: a carry out of the top bit is added back into the lowest bit. For example, 0101 (+5) + 1110 (−1) gives 1 0011; adding the carry back gives 0100 (+4). Two’s complement has one zero and needs no such correction, at the price of a range that is not quite balanced.

Two’s complement and bias

To form −x in n-bit two’s complement, invert all n bits of x and add 1; discard a carry beyond the width. The minimum value −2n−1 is the exception: its positive counterpart is outside the signed range, so fixed-width negation leaves the same pattern and overflows. Why inverting and adding one works: inverting x gives (2n−1)−x, because each bit becomes 1 minus itself. Adding 1 gives 2n−x, which is exactly the pattern for −x modulo 2n. Equivalently, interpret a pattern with top bit 1 by subtracting 2n from its unsigned value. In excess-B notation, actual value = stored unsigned value − B. The lecture’s three-bit excess-4 example therefore maps 000 to −4 and 111 to 3. Bias has a practical reason: the order of the true values matches the unsigned order of the stored patterns, so comparing two excess values is a plain unsigned comparison.

Decode rulesTwo’s-complement value = unsigned(pattern) − 2n when the top bit is 1Negate x: invert n bits, then add 1Excess-B value = stored value − BKeep the width fixed throughout. The same bit pattern has no signed meaning until an encoding is specified.

BCD stores decimal digits separately

In four-bit BCD, each decimal digit has its own four-bit code. For example, decimal 59 is 0101 1001 in BCD, while the ordinary binary value 59 is 00111011. BCD uses more bits but keeps each decimal digit directly readable.

Trap: do not convert all BCD bits as one binary number. Decode each four-bit group as a decimal digit.

3.3 Character data

Numbers are not the only data stored as bits. A character encoding assigns numeric codes to letters, digits, punctuation, and control characters.

ASCII and Unicode

ASCII uses seven bits, giving 128 code values. The lecture describes eight-bit extensions that use the additional 128 patterns, but those upper values depend on the particular extension. Unicode assigns code points to characters across many writing systems; its first 128 code points match ASCII. A code point and its byte encoding are related but are not the same concept.

Character-code facts7-bit ASCII: 27 = 128 code valuesASCII code points: 0 … 127The first 128 Unicode code points correspond to ASCII. Byte encodings represent code points as bytes by their own rules.

Worked encoding · read a short ASCII string

The lecture’s example encodes “Fred” in hexadecimal as 46 72 65 64.

  1. Split the bytes: 46, 72, 65, 64.
  2. Read each as a hexadecimal ASCII code: 46 is F, 72 is r, 65 is e, and 64 is d.
  3. The four codes decode to “Fred”. §3.3

Trap: an encoding is a mapping, not a property of the bit pattern by itself. Identify the character set and any byte encoding before decoding text.

3.4 Unsigned binary arithmetic

Binary arithmetic follows the same place-value logic as decimal arithmetic. Carries and borrows move between columns, while the fixed bit width limits which values can be stored.

Add and subtract

Add each column and carry 1 when a column totals 2. For subtraction, borrow from a higher column when the current minuend bit is too small; a borrowed binary 1 is worth 2 in the current column. Subtraction can also be checked by adding the difference to the subtrahend.

Worked addition · include the carry

Add 1110112 and 1010102.

  1. From right to left: 1+0=1.
  2. 1+1=10, so write 0 and carry 1. Continue each column with its carry.
  3. The result is 11001012. Check: 59+42=101, and 11001012=101. §3.4

Worked subtraction · borrow across a zero

Calculate 10102−00112.

  1. Rightmost column: 0−1 needs a borrow from the next column, so 2−1=1, and that column’s 1 becomes 0.
  2. Next column: 0−1 needs a borrow, but the column to its left is 0, so take from the top bit. The top bit becomes 0, the third column keeps 1, and this column gets 2: 2−1=1.
  3. Third column: 1−0=1. Top column: 0−0=0.
  4. The result is 01112. Check: 10−3=7. §3.4

Multiply and divide

Binary multiplication uses partial products, like decimal long multiplication, but each multiplier bit is only 0 or 1. Binary division uses quotient and remainder. For divisor d≠0, dividend = quotient×divisor + remainder, where 0≤remainder<divisor.

Division checkdividend = quotient × divisor + remainder0 ≤ remainder < divisorSubstitute the quotient, divisor, and remainder to check a division result.

Worked multiplication · partial products

Calculate 11012×1012.

  1. Multiplier bit 1 (rightmost): write 1101.
  2. Multiplier bit 0: the partial product is zero.
  3. Multiplier bit 1 (two places left): write 110100.
  4. Add: 1101+110100=10000012. Check: 13×5=65. §3.4

Worked division · long division

Calculate 101112÷112.

  1. 10 is smaller than 11, so take 101: quotient bit 1, remainder 101−11=10.
  2. Bring down 1 to get 101: quotient bit 1, remainder 10.
  3. Bring down 1 to get 101: quotient bit 1, remainder 10.
  4. Quotient 1112, remainder 102. Check: 7×3+2=23. §3.4

Memory hook: in binary addition, 1+1 writes 0 and carries 1. In subtraction, a borrow makes the current column worth 2 before subtracting.

3.5 Two’s-complement arithmetic and overflow

Two’s complement lets the same adder perform signed addition and subtraction. Correct bit operations still need a range check: a fixed-width result can wrap to a pattern with a different signed value.

Addition, subtraction, and overflow

Add the bit patterns and discard any carry beyond the most significant bit. For subtraction, negate the subtrahend and add it to the minuend. Signed overflow occurs when the exact mathematical result lies outside the representation’s range. For addition, it occurs when two operands with the same sign produce a result with the opposite sign; operands of unlike signs cannot overflow.

n-bit two’s-complement checksRange: −2n−1 … 2n−1−1A − B = A + (two’s-complement negation of B)Same-sign addition with opposite-sign result ⇒ overflowDiscarding carry-out is part of fixed-width addition. Carry-out alone does not signal signed overflow.

Worked example · detect overflow

Use four-bit two’s complement to calculate −7+(−6).

  1. Encode −7 as 1001 and −6 as 1010.
  2. Add: 1001+1010=1 0011. Discard the carry-out, leaving 0011.
  3. The stored result 0011 is +3, but the exact sum is −13, outside the four-bit range −8…+7. Both inputs were negative and the result is positive, so overflow occurred. §3.5

Multiplication and division

The lecture notes that ordinary unsigned multiplication cannot simply be applied to signed two’s-complement patterns and read at the original width. A full product may require up to twice as many bits as the operands; retain a sufficient width and interpret the result consistently. For a simple signed multiplication, multiply magnitudes and make the result negative exactly when the operand signs differ, then check the available width. The supplied slides introduce this idea but do not give a complete signed division algorithm.

Worked multiplication · signed values

Calculate (−3)×(+5) and store it in eight-bit two’s complement.

  1. Multiply magnitudes: 3×5=15=000011112.
  2. The signs differ, so the result is negative.
  3. Negate in eight bits: invert to 11110000 and add 1, giving 11110001.
  4. Check: 241−256=−15, inside −128…+127. Four bits could not hold it. §3.5

Overflow also matters for safety. The lecture warns that an integer overflow in a memory-size calculation can become a security hole, such as a buffer overflow, because too little memory gets allocated.

Sign check: do not treat discarded carry as overflow. Decode the fixed-width result and compare it with the exact mathematical result and allowed range.

4.1 The floating-point model

Fixed-width integers from §3.5 cannot hold fractions or very large and very small values. Floating point uses a sign, a significand, and an exponent to cover those magnitudes, at the cost of exactness.

Range and precision

For base β, a normalised number has the form sign × significand × βexponent. The exponent controls scale and therefore the approximate range. The number of significand bits controls precision, or how finely nearby values can be distinguished.

Floating-point values are finite in number, and their spacing changes with magnitude.

Scientific notation modelx = s × M × βEs is the sign, M is the significand, β is the base or radix, and E is the exponent. In binary floating point, β=2.
Local gap between neighboursgap within [2E, 2E+1) = 2E−p+1p is the number of significand bits. (This follows directly from the notes’ model: the last of p bits has weight 2−(p−1), scaled by 2E. The notes only say the gap grows.) Between 8 and 16, E=3, so p=24 gives 2−20.

Worked example · normalise a decimal value

Write 343000 × 10−4 in normalised decimal form with 1≤M<10.

  1. Move the decimal point in 343000 five places left to make 3.43.
  2. Increase the exponent by five to preserve the value: 3.43 × 101.
  3. Check: 343000 × 10−4=34.3, and 3.43 × 101=34.3. §4.1

Trap: moving the radix point changes the exponent in the opposite direction if the represented value is to stay the same.

4.2 Binary fractions

The significand from §4.1 is a binary fraction, so its place values explain both conversion and approximation.

The first bit after the binary point has weight 2−1, and each following bit has half the previous weight.

Convert binary fractions to decimal

Binary fractional place values0.b1b2…bk = b12−1 + b22−2 + … + bk2−kEach bi is 0 or 1. A leading integer part is evaluated with non-negative powers of 2.

Worked conversion · binary fraction to decimal

Convert 0.011012 to decimal.

  1. Use the five place values: 1/2, 1/4, 1/8, 1/16, and 1/32.
  2. Keep the places where the bit is 1: 1/4 + 1/8 + 1/32.
  3. Add: 0.25+0.125+0.03125=0.40625. §4.2

Convert decimal fractions to binary

Repeatedly multiply the fractional part by 2.

At each step, the integer part is the next binary digit, and the new fractional part is carried into the next step.

Worked conversion · terminating binary fraction

Convert 0.6875 to binary.

  1. 0.6875×2=1.375, so the first bit is 1; carry 0.375.
  2. 0.375×2=0.75, so the next bit is 0; carry 0.75.
  3. 0.75×2=1.5, so the next bit is 1; carry 0.5.
  4. 0.5×2=1.0, so the next bit is 1; the fraction is now zero.
  5. Therefore 0.6875=0.10112. Check: 1/2+1/8+1/16=0.6875. §4.2

Some fractions, such as 0.1 in decimal, repeat in binary.

A finite significand stores only an approximation of a repeating expansion.

Trap: a decimal fraction that looks short is not necessarily exact in binary.

4.3 Floating-point arithmetic and error

The exponent and significand must be managed during each operation.

After the exact operation, the result may need normalisation and rounding to fit the available precision.

Multiplication

Multiply normalised values(M1 × βE1)(M2 × βE2) = (M1M2) × βE1+E2Multiply the significands and add the exponents. Then normalise and round if needed.

Worked multiplication · normalise the result

Calculate (2.6×103)(5.4×10−2).

  1. Multiply significands: 2.6×5.4=14.04.
  2. Add exponents: 3+(−2)=1, giving 14.04×101.
  3. Normalise: 1.404×102=140.4. §4.3

Addition

Before adding, express both numbers with the same exponent.

Shift the significand of the value with the smaller exponent to the right by the exponent difference.

This alignment can discard low-order digits before the addition is even performed.

Worked addition · align exponents

Use two significant decimal digits to add 4.5×103 and 6.7×102.

  1. Rewrite the second value at exponent 3: 6.7×102=0.67×103.
  2. Add significands: (4.5+0.67)×103=5.17×103.
  3. Round to two significant digits: 5.2×103. The exact sum is 5170, while this two-digit result is 5200. §4.3

Rounding, overflow, and comparison

Truncation drops extra digits and tends to bias results in one direction.

Rounding chooses a nearby representable value and usually gives a better approximation.

Exponent overflow occurs when the result is too large for the format.

Exponent underflow occurs when the result is too small for the normalised range.

The slides describe infinity or an exception for overflow, and zero or an exception for underflow in their simplified model.

IEEE formats also provide subnormal numbers near zero.

For approximate comparisons, choose a tolerance ε that fits the scale and precision of the problem.

Absolute tolerance exampleTreat a as close to b when |a−b| < εFor b = 1 and ε = 0.000005: 0.999995 < a < 1.000005A fixed absolute tolerance may be unsuitable when magnitudes vary greatly. The slides also introduce relative closeness.

Sign check: estimate the order of magnitude before accepting a rounded result.

4.4 IEEE 754 binary formats

A shared format defines how floating-point fields are stored and how arithmetic behaves.

The slides introduce IEEE 754 as a widely adopted standard for predictable binary floating-point arithmetic.

Single and double precision

Single32 bits1 bit8 bits23 bits24 bits for normal values127
Double64 bits1 bit11 bits52 bits53 bits for normal values1023

For a normalised binary value, the leading significand bit is 1 and is omitted from the stored fraction field.

The exponent field stores a biased exponent rather than a two’s-complement exponent. Stored order then matches true order, so hardware can compare two exponents as plain unsigned integers.

Normalised value rulevalue = (−1)S × 1.F × 2E−biasSingle bias = 127double bias = 1023S is the sign bit, E is the unsigned exponent field, and F is the stored fraction interpreted after the binary point. This rule is for normalised values.

Convert decimal to single precision

Worked conversion · 42.6875

  1. Convert to binary: 42.6875=101010.10112.
  2. Normalise: 1.010101011×25, so the sign bit is 0.
  3. Store the fraction after the hidden leading 1: 01010101100000000000000.
  4. Bias the exponent: 5+127=132=100001002.
  5. The fields are 0 | 10000100 | 01010101100000000000000, or hexadecimal 422A C000. §4.4

Decode single precision

Worked decoding · BEC0 0000

  1. The sign bit is 1, so the value is negative.
  2. The exponent field is 011111012=125; subtract the bias: 125−127=−2.
  3. Restore the hidden bit: 1.1000…2=1.5.
  4. Scale: 1.5×2−2=0.375. Apply the sign: −0.375. §4.4

Trap: restore the hidden leading 1 when decoding a normalised value, but do not apply that rule to a subnormal value.

4.5 Zero, subnormal numbers, infinity, and NaN

Reserved exponent patterns extend useful behaviour beyond normalised values.

In single precision, exponent field zero and exponent field all ones have special interpretations.

Exponent fieldFraction fieldMeaning

Subnormal value rulevalue = (−1)S × 0.F × 2−126Smallest normal single: 2−126 ≈ 1.175×10−38For a subnormal single-precision number, the hidden bit is 0 and the exponent is fixed at −126. Precision falls as the value nears zero.

Subnormal values fill the gap between the smallest normal value and zero, so underflow is gradual. They also keep the property x−y==0 exactly when x==y, even for very small numbers.

They can be slow: many CPUs handle them through a microcode assist or a software trap, which the lecture calls orders of magnitude slower. Flush-to-zero (FTZ) is a non-compliant mode that treats subnormals as zero. It is faster but gives up that correctness, and high-performance programs often enable it.

Infinity represents overflow results and some divisions by zero. NaN represents an operation without a real-number result, such as 0/0, √−1 or infinity−infinity.

Before IEEE 754, such operations could trap and end the program. With these values the computation continues, and the status propagates to be checked later.

Operations on infinity and NaN follow format rules, not ordinary real-number algebra in every case.

Numerical stability and cancellation

Cancellation occurs when subtracting close stored values. The subtraction may itself be exact, yet earlier rounding in the operands can dominate the small difference. A stable method avoids needlessly creating that sensitive subtraction.

Machine epsilon and relative error

Machine epsilon is the gap from 1 to the next larger representable value. For radix β and p significant digits, εmach=β1−p. Here p counts the full significand digits, including the hidden leading bit in a normalised IEEE value.

Binary machine epsilonSingle precision: p = 24, εmach = 2−23 ≈ 1.19×10−7Double precision: p = 53, εmach = 2−52 ≈ 2.22×10−16Under round-to-nearest, the unit roundoff u is εmach/2 for normal results. “Unit roundoff” is not a term from the slides.
Relative rounding modelfl(x) = x(1+δ), with |δ| ≤ uFor finite non-zero normal results, round-to-nearest, and no overflow. Relative error is measured against |x|, so the same absolute error matters more when the true answer is small.

The slides bound the error by ε; under round-to-nearest the tight bound is ε/2 (= u). Both statements are true; use the slide form if the exam asks for it.

Error propagation in a differencex′ = x(1+δx), y′ = y(1+δy)relative error = ((x′−y′)−(x−y))/(x−y) = (xδx−yδy)/(x−y)The numerator stays about the size of the input errors. As x approaches y the denominator approaches zero, so the relative error can explode.

Worked example · cancellation

Suppose five significant decimal digits store x=0.123456789 as 0.12346 and y=0.123451234 as 0.12345.

  1. The exact difference is 0.000005555.
  2. The stored difference is 0.00001.
  3. The stored difference is about 1.80 times the exact difference, so its relative error is about 80.0%. The subtraction exposed input rounding error. §4.5

Sterbenz lemma

If x and y are positive finite floating-point values in the same radix and precision, and y/2≤x≤2y, then x−y is exactly representable when gradual underflow is supported. For example, 1.5 and 1.0 meet the condition, and their difference 0.5 is exact. This does not undo rounding that happened while x or y was computed; cancellation can expose that earlier error.

Stable quadratic roots

For ax2+bx+c=0, require a≠0 and D=b2−4ac≥0. The usual formula can subtract nearly equal quantities for one root. For D>0, choose the branch that adds magnitudes: if b≥0, set q=−½(b+√D); if b<0, set q=−½(b−√D). Then the roots are q/a and c/q. This branch also handles b=0. For D=0, use the repeated root −b/(2a), since q may be zero. These steps avoid cancellation while respecting the degenerate cases.

The notes write the same method as x1=(−b−sgn(b)√D)/(2a) and x2=c/(a x1). Since q=a·x1, c/q is the slide’s c/(a x1). The second form comes from expanding a(x−x1)(x−x2): matching the constant term gives x1x2=c/a, which is Vieta’s relation, so x2 needs no subtraction.

Worked example · x2+108x+1=0 in double precision

  1. Here a=1, b=108, c=1, so D=1016−4 and √D≈108.
  2. Direct formula for the small root: (−b+√D)/2 subtracts nearly equal values and gives about −7.45×10−9.
  3. Stable: b≥0, so q=−½(b+√D)≈−108. The roots are q/a≈−108 and c/q≈−10−8.
  4. Check: the product of the roots is 1=c/a, and the sum is about −108=−b/a. The direct value was about 25% off. §4.5

Trap: mathematical equivalence does not guarantee equal numerical accuracy. Look for subtraction of nearly equal values and avoid rounding intermediate results unnecessarily.

Fused multiply-add

A fused multiply-add evaluates a×b+c with one final rounding. Separate multiplication and addition can round the product first, then round again after addition. FMA can therefore preserve more information; its speed benefit depends on hardware. The lecture names dot products, matrix multiplication and polynomial evaluation as algorithms that gain from it.

Fused versus separate roundingFMA(a,b,c) = round(a×b+c)Separate: round(round(a×b)+c)The fused operation avoids the intermediate rounding step.

5.1 C memory and pointers

Everything so far gave meaning to bit patterns. C also lets you handle where those patterns live, because an address is itself a number you can store. That gives direct control and direct ways to fail.

Addresses, & and *

C treats memory as a contiguous line of bytes, each with a numerical address, usually written in hexadecimal. A pointer is a variable that stores an address. The operator & gives the address of a variable, and * reads or writes the value at an address.

Core syntaxint *p; declares a pointer to intint x = 10; p = &x; p now holds the address of x*p = 20writes through p, so x becomes 20In a declaration, * builds a pointer type. In an expression, * dereferences.

Pointer arithmetic and arrays

Adding n to a pointer moves n elements, not n bytes. In most expressions an array name decays to a pointer to its first element, and subscripting is defined through that pointer.

Scaling and subscriptsnew address = old address + n × sizeof(type)a[i] means *(a + i)Sizes depend on the platform; the lecture assumes 4 bytes for int and 8 for double.

Worked example · scaled steps

With int a[10]; int *p = &a[0]; the array starts at 0x1000, and sizeof(int) is 4.

  1. p+1 is 0x1000+1×4=0x1004, the address of a[1].
  2. p+3 is 0x1000+3×4=0x100C, because 12 is C in hexadecimal. This is the address of a[3].
  3. For struct Point { double x; double y; } each element takes 2×8=16 bytes, so the same +1 step moves 16 bytes. Check: the step always equals the element size. §5.1

A function that receives an array actually receives a copy of the pointer to its first element. That is why arrays appear to be passed by reference.

Double pointers and function pointers

C passes every argument by value, so a function given a pointer gets a copy and cannot change the caller’s pointer. To let it do so, as an allocating function must, pass the address of the pointer. A pointer to a pointer adds one level of indirection: with int **p2 = &p1; *p2 is p1 and **p2 is the int.

Changing the caller’s pointervoid allocate(int **ptr, int size) { *ptr = malloc(size * sizeof(int)); }int *my = NULL; allocate(&my, 10);Inside the function, *ptr is the caller’s my itself.
Function pointersint (*op)(int, int) = add; result = (*op)(5, 3);A pointer can hold the address of code. Passing one to another function gives a callback, as in qsort or event handlers. With add returning a+b, result is 8.

5.2 The Python memory model

Python keeps the reference idea from §5.1 but hides the addresses and the freeing. Knowing the model tells you when a change through one name shows up through another.

Names, objects and rebinding

A C variable is a typed box that holds a value. A Python variable is a name bound to an object that lives elsewhere, and all data, including integers and functions, are objects. The built-in id() gives an object’s identifier, which in CPython is its memory address, so you can see when two names share an object. In C, x = 20 overwrites the box. In Python, x = 20 rebinds the name to another object and leaves the old object unchanged.

Worked trace · shared reference then rebinding

Trace a = [1, 2, 3]; b = a; b.append(4); b = [0]; print(a).

  1. a = [1, 2, 3] makes one list object and binds a to it.
  2. b = a binds a second name to the same object, so id(a) equals id(b).
  3. b.append(4) changes that object, so a now shows [1, 2, 3, 4].
  4. b = [0] rebinds b only. print(a) gives [1, 2, 3, 4]. Check: exactly one statement changed the object a refers to. §5.2

Mutability and function arguments

Immutable objects (int, float, str, tuple) cannot change after creation, so operations make new objects. Mutable objects (list, dict, set) can change in place, and the change is visible through every name that refers to them.

A function receives a reference to the object, which is called pass-by-object-reference. It cannot change what the caller’s name refers to, but it can change a mutable object’s contents. With data = [1, 2, 3], a function calling some_list.append(4) leaves data as [1, 2, 3, 4].

Automatic memory management

Reference counting is the main mechanism: each object counts the references to it, and when the count reaches zero it is freed at once. These references include list slots and other containers, not only names. A generational garbage collector runs periodically to find reference cycles, such as two objects that refer to each other, which counting alone cannot free.

Show model explanations
  1. The rightmost place is position zero, and any base raised to zero is 1. Its bit contributes either zero or one to the value.
  2. Each octal digit maps to exactly three bits and each hexadecimal digit to four. Grouping bits preserves their value while shortening the written form.
  3. Both encodings use a sign bit and a separate magnitude/complement pattern for zero. That creates distinct positive-zero and negative-zero bit patterns.
  4. With n bits, one pattern is used for zero and the remaining patterns cannot be divided evenly into equal positive and negative ranges. Two’s complement assigns the extra pattern to the negative side.
  5. Fixed-width addition retains only n result bits, so carry beyond the word is discarded. Signed overflow depends on the signs of the inputs and result, not on that discarded bit.
  6. Each four-bit BCD group can be read as one decimal digit, but four bits are used per decimal digit even when ordinary binary could represent the whole number with fewer bits.
  7. The exponent scales a significand by powers of the base, expanding which magnitudes can be represented. Precision depends chiefly on how many significand bits distinguish values at a given scale.
  8. At a larger exponent, the same significand step is multiplied by a larger power of 2. Therefore adjacent representable values are farther apart.
  9. A finite binary fraction has a denominator that is a power of 2 after reduction. One tenth has a factor of 5 in its denominator, so its binary expansion repeats.
  10. Only values with the same exponent have significands describing the same scale. Alignment expresses both at a shared scale before combining them.
  11. Alignment shifts the smaller significand to the right. If the exponent difference is large, its significant bits may fall beyond the available precision.
  12. Every normalised binary number begins with 1 before the point, so the format can infer that bit and use its storage for another fraction bit.
  13. A subnormal represents a non-zero value smaller than the minimum normalised magnitude, close to zero.
  14. Absolute or relative error that is acceptable depends on the scale and purpose of the calculation. One fixed tolerance may be too strict for large values or too loose for small ones.
  15. Spacing scales with the exponent, so a fixed absolute difference is a different fraction of values at different magnitudes. Machine epsilon measures spacing near 1; the relative rounding model expresses error as a fraction of the input magnitude.
  16. For positive floating-point x and y with y/2≤x≤2y, their difference is exactly representable under the format assumptions. Any rounding that already changed x or y can still affect the difference.
  17. Stored order then matches true order. Exponents can be compared as plain unsigned integers, which is simple and fast in hardware.
  18. C copies every argument, so the function holds its own copy of the address. Changing that copy leaves the caller’s pointer alone, which is why it must receive the pointer’s address instead.
  19. Both names refer to the same object, so append changes what the caller sees. Assignment only rebinds the local name to another object.
  20. Two objects that refer to each other keep each other’s count above zero even when nothing else can reach them. Counting alone would never free them, so a periodic collector finds such cycles.

Exam-style problems

Allow about 20 minutes for each problem. Attempt each part before opening its worked answer.

Problem 1 · Compare encodings

Encode −5 in four-bit sign-and-magnitude, one’s complement and two’s complement.

  1. Write the four-bit pattern in each encoding.
  2. State the range and number of zero patterns for each representation.
  3. Explain why two’s complement is useful for arithmetic despite its asymmetric range.
Show the worked answer
  1. +5 is 0101. Sign-and-magnitude is 1101. One’s complement is 1010, the inversion of 0101. Two’s complement is 1011, the inversion plus 1. §3.2
  2. For four bits, sign-and-magnitude and one’s complement both range from −7 to +7 and have two zero patterns. Two’s complement ranges from −8 to +7 and has one zero. §3.2
  3. Negation and subtraction use the same fixed-width adder: invert the subtrahend and add one. Its one extra negative value is usually a small trade-off for simpler arithmetic hardware. §3.2 §3.5

Problem 2 · Convert, calculate, and check

In four-bit two’s complement, compute −5 + 3.

  1. Write both input patterns and add them, showing any carry-out.
  2. Decode the retained four-bit result and compare it with the exact sum.
  3. State whether overflow occurred and explain why carry-out is not the test.
Show the worked answer
  1. −5 is 1011 and +3 is 0011. Addition gives 1110 with no carry-out. §3.5
  2. 1110 is 14 unsigned; subtract 16 to decode −2. The exact sum is also −2. §3.2 §3.5
  3. No overflow: the exact result −2 lies in −8…+7. Carry-out is not the signed-overflow criterion; compare the signs or the exact result to the range. §3.5

Problem 3 · Encode and decode single precision

Store 13.25 in IEEE single precision.

  1. Convert 13.25 to binary.
  2. Normalise it and identify sign, exponent, and stored fraction.
  3. Give the exponent field and verify by decoding.
Show the worked answer
  1. 13.25=1101.012, since 13=11012 and 0.25=0.012. §4.2
  2. Normalise: 1.10101×23. The sign is 0. The stored fraction is 10101000000000000000000 after padding to 23 bits. §4.4
  3. Biased exponent is 3+127=130=100000102. The pattern is 0 | 10000010 | 10101000000000000000000. Decoding restores 1.101012×23=13.25. §4.4

Problem 4 · Align, add, and assess precision

Add 3.4×104 and 5.6×102 using two significant decimal digits.

  1. Align both values to exponent 4.
  2. Add the significands and round to two significant digits.
  3. Compare the rounded result with the exact decimal sum and explain the source of the difference.
  4. Find the relative error and compare it with the unit roundoff of this two-digit decimal format.
Show the worked answer
  1. 5.6×102=0.056×104. §4.3
  2. (3.4+0.056)×104=3.456×104, which rounds to 3.5×104. §4.3
  3. The exact sum is 34560 and the rounded result is 35000. The smaller addend contributes digits beyond the two-digit precision, so rounding changes the stored result. §4.3
  4. The relative error is 440/34560≈1.27%. With β=10 and p=2, ε=10−1 and u=0.05, so the error is within the 5% bound. §4.5

Problem 5 · From addresses to names

In C, int a[4] starts at 0x2000 and sizeof(int) is 4, with int *p = a;. In Python, def f(s): s.append(1); s = [] is called as t = [0]; f(t).

  1. Give the address p+3 in hexadecimal, and two other ways to write the element there.
  2. A C function sets its int * parameter to NULL. Does p change? Give the signature that would change it.
  3. State what print(t) shows and which line of f affects it.
  4. Compare how the C and Python functions reach the caller’s data.
Show the worked answer
  1. 0x2000+3×4=0x200C. The element is a[3], or *(p + 3). §3.1 §5.1
  2. No, the parameter is a copy. Use int ** and pass &p. §5.1
  3. [0, 1]. The append changes the shared list; s = [] only rebinds the local name. §5.2
  4. C copies an address, and the function writes through it with *. Python copies a reference, and the function changes a mutable object. Neither can rebind the caller’s own variable through a plain parameter. §5.1 §5.2

Slips in the notes

Entries were checked against the slides, some only as extracted text, so confirm any entry against the slide itself before relying on it. “Slide” means a slide of “APDR lecture 2 extended” unless stated. Where the guide differs from the notes, this list says so; items marked as notation or simplification are not errors of value.

  • Chapter 3 slide 24: the four-bit Excess-8 row for 0111 is printed as 1; stored value 7 minus bias 8 gives −1. §3.2
  • Slide 3 against slide 5 (uneven claim): a balanced range is listed as desirable and only the older encodings are said to fail. Two’s complement also misses it, as slide 5 itself shows. §3.2
  • Slide 6: the C example says assigning 127+1 to signed char wraps to −128. That is not guaranteed by C: integer promotion computes 128 as int, then converting an out-of-range value to signed char has an implementation-defined result or signal. Do not generalise this example as signed integer overflow being defined wraparound. See clauses 6.3.1.1 and 6.3.1.3 of the WG14 C standard draft N1570. §3.5
  • Slide 17 (simplification): the performance cost of subnormals depends on the CPU and its mode. The guide reports it as the lecture’s statement. §4.5
  • Slides 18–19: ε is called the upper bound on relative rounding error. That holds, but under round-to-nearest the tight bound is ε/2, which the guide calls u. Slide 19’s “any real number x that can be represented” means any x within range. §4.5
  • Slide 21: Sterbenz’s lemma is stated without its conditions. The guide adds positive values of the same format, and gradual underflow. §4.5
  • Slide 22: x1 with sgn(b) breaks at b=0 if sgn(0)=0, because it gives x1=0 and then c/(a·0). The slide also leaves a≠0 and D≥0 unstated. The guide’s branch treats b=0 as b≥0 and requires both. §4.5
  • Slide 26: “int arr;” declares one int, yet the text calls it an array and labels p+1 and p+3 both “address of arr”. The brackets were probably lost; the guide reads int a[10], a[1] and a[3]. §5.1
  • Slide 27: “int int_array;” and “struct Point pt_array;” have probably lost their sizes in the same way. “sizeof(Point)” needs “struct Point” in C, and the sizes 4 and 16 assume a platform. §5.1
  • Slide 28: “array is equivalent to array” is a tautology. It reads as if it should be array equivalent to &array[0]. §5.1
  • Slide 32: dereferencing NULL is said to cause a crash always. It is undefined behaviour; a crash is only typical. The fix printed as “p = some ariable” should be p = &some_variable. §5.1
  • Slides 35 and 38: “a =”, “data =” and the printed outputs have lost their list literals. The guide supplies [1, 2, 3], which is an assumption, chosen to fit the append(4). §5.2
  • Slide 39 (simplification): the count is described as names that refer to an object. It counts all references, including list slots. §5.2
