5.1 Memory hierarchy and properties

Hierarchy balances speed, capacity, cost, volatility, and flexibility. Registers are fastest and smallest; storage devices are largest and slowest.

Memory hierarchyfastest/smallest → registers → RAM → storage → largest/slowestThis is a qualitative ordering, not a universal timing specification.

Memory holds data, instructions, and addresses as binary values. Contents change only when overwritten. Registers are fixed in the CPU; RAM is expandable main memory; disks and other devices provide expandable storage. The lecture’s comparison is qualitative: registers are expensive, small, fast, volatile; RAM is intermediate; disks are cheap, large, slower, and non-volatile.

SRAM and DRAM

Static RAM (SRAM) is fast, less dense because each bit needs more transistors, and used mainly for cache; the slides also say it consumes less power. Dynamic RAM (DRAM) stores a bit in a transistor and capacitor. The capacitor leaks its charge, so DRAM must be refreshed periodically. It is cheaper but slower than SRAM and is used mainly for main memory.

TypeCell and behaviourMain use in the lecture
SRAMMore transistors per bit; faster, less dense, lower powerCache
DRAMTransistor and capacitor; needs periodic refreshMain memory

Worked example

A program, its data, and pointers to both can all be represented as binary values.

  1. CPU instructions, data values, and addresses all use binary storage. §5.1

5.2 RAM cells, addressing, and capacity

A memory needs a way to identify locations and a unit that each address selects.

Memory sizeR rows × W bits per row = R×W bitsAddress count depends on address width and the addressable unit.

RAM can be modelled as R rows of W bits: total capacity is R×W bits. Byte-addressable memory assigns one address to each byte; word-addressable memory assigns one address to each processor word. For n address bits there are 2n distinct addresses. If each address selects one byte, capacity is 2n bytes. The slides use binary capacity units: 1 KB=210 bytes, 1 MB=220, 1 GB=230, 1 TB=240.

Worked example

The lecture’s 1GB example has 256M rows × 32 bits = 8,192M bits = 1,024M bytes = 1 GiB (binary units).

  1. 256M rows times 4 bytes per row equals 1,024M bytes. §5.2

5.3 Endianness and aligned access

When a value spans multiple bytes, the byte order determines what appears at increasing addresses.

Byte orderBig-endian: MSB at lowest address · Little-endian: LSB at lowest addressThe starting address is the address of the first byte of the item.

Big-endian stores the most significant byte first; little-endian stores the least significant byte first. Endianness changes the order of bytes in one multi-byte item, not the bit order inside each byte. A character string treated as individual ASCII bytes therefore retains its character order. Some architectures prohibit unaligned multi-byte accesses; the lecture identifies this as architecture-dependent.

Worked example

A 16-bit value A9A1 beginning at byte address 2 is aligned in the slide’s example; F021 beginning at address 7 is unaligned.

  1. Determine alignment from the access width and starting address; the lecture’s examples contrast 2 with 7. §5.3

5.4 Memory chips and modules

Chip organisation connects a chip’s row count and data width to the capacity and width of a module.

Chip capacityrows × bits per row = bits; divide by 8 for bytesHere M means 220, as in the lecture’s capacity convention.

A chip described as 128M×8 stores 128M rows of 8 bits, or 128 MB using the lecture’s binary convention. Chips can be combined in parallel to widen a module, and multiple banks/modules can build larger capacity. The slides show a 1GB (256M×32-bit) memory assembled from alternative combinations of chips and modules.

Worked example

Four 128M×8 chips provide 128M rows of 32 bits, or 512 MiB. Two such modules provide 1 GiB.

  1. Width combines in parallel; module capacity is rows times total width. §5.4

5.5 Memory interleaving

Interleaving assigns addresses across modules so independent modules can serve requests in parallel.

Address split for four modules22 address bits = 2 module bits + 20 row bitsThe 2 module bits select one of four modules; the 20 row bits select a row.

The lecture’s example has 4M words, each 32 bits, built from four 1M×32 modules. A 22-bit word address splits into 2 module bits and 20 row bits. High-order interleaving places module bits at the high end: consecutive addresses stay in one module for a large region. Low-order interleaving places module bits at the low end: consecutive addresses cycle across modules, supporting parallel access to adjacent data.

Worked example

Low-order interleaving sends adjacent addresses to different modules; high-order interleaving groups a large contiguous range in one module.

  1. The address-bit positions determine whether nearby addresses are distributed or grouped. §5.5

Trap: state the addressable unit, width, and byte order before calculating. Do not treat a qualitative lecture comparison as a fixed hardware specification.

Exam-style problems

1 · Build and read a memory module · 20 minutes

A system has 4M words of 32 bits, built from four 1M×32 modules. It is byte-addressable and uses low-order interleaving.

  1. How many address bits are needed for all words?
  2. How many module bits and row bits are used?
  3. Which module and row receive word addresses 0 through 7?
  4. Explain why sequential access may benefit.
Show the worked answer
  1. 4M=222 words, so 22 word-address bits are needed. Each word is 4 bytes, so byte addresses would require 24 bits if byte-addressing the entire space. §5.2
  2. For the lecture’s word-addressed interleave example, 2 bits select one of four modules and 20 bits select the row. §5.5
  3. Using word addresses 0–7: modules cycle 0,1,2,3,0,1,2,3, with row 0 for the first four and row 1 for the next four. §5.5
  4. Adjacent words are in different modules, so a capable memory system may overlap accesses. §5.5

2 · Endian bytes and capacity · 20 minutes

The 32-bit value 0x54BCFE30 begins at byte address 24 in a byte-addressable memory.

  1. List the four bytes at addresses 24–27 in big-endian order.
  2. List them in little-endian order.
  3. How many bits are needed to address 4 GiB of byte-addressable memory?
  4. State the capacity of a 256M×32-bit memory.
Show the worked answer
  1. 54, BC, FE, 30. The most significant byte is first. §5.3
  2. 30, FE, BC, 54. The least significant byte is first. §5.3
  3. 4 GiB=232 bytes, so 32 address bits are required. §5.2
  4. 256M×32÷8=1,024M bytes=1 GiB. §5.4
