Number and Data Representation

Algorithms, Programming, and Data Representation · Module 92313 · Chapter 3

This chapter shows how bit patterns encode numbers and characters, then uses those representations to perform arithmetic. The meaning of a bit pattern depends on the encoding and the number of bits.

3.1 Number systems and positional notation

A numeral is a compact way to write a sum of place values. Binary, octal, decimal, and hexadecimal use the same positional rule with different bases.

Expand and convert

In base b, each digit di contributes dibi, where the rightmost digit has i=0. Binary digits are 0 or 1. Decimal-to-binary repeated division records remainders; read them from last to first.

Positional value(dk…d1d0)b = ∑i=0k dibi(1100010)2 = 1·26 + 1·25 + 1·21 = 98The worked binary number is 98 in decimal. Subscripts identify the base.

Worked conversion · decimal to binary

Convert 45 to binary by repeated division.

  1. 45 ÷ 2 gives quotient 22, remainder 1.
  2. 22 ÷ 2 gives quotient 11, remainder 0; then 11 gives 5 remainder 1.
  3. Continue: 5 gives 2 remainder 1; 2 gives 1 remainder 0; 1 gives 0 remainder 1.
  4. Read remainders upward: 1011012. Check: 32+8+4+1=45. §3.1

Octal and hexadecimal

Because 8=23, each octal digit corresponds to three binary digits. Because 16=24, each hexadecimal digit corresponds to four bits. Group binary digits from the right and pad the leftmost group with zeroes if needed. In hexadecimal, A–F mean 10–15.

Compact binary groups101012 = 010 101 = 258100101002 = 1001 0100 = 94161 byte = 8 bits = 2 hexadecimal digitsThe lecture uses 16-bit words and 32-bit long words as examples; the sizes named by these terms can depend on a computer architecture. (This goes beyond the notes, which give only those examples.)

Trap: do not read a binary string as an ordinary decimal integer. Attach its base, expand it, and only then compare values.

3.2 Integer representations

A computer stores a fixed number of bits, not a plus or minus sign unless the encoding defines one. The same pattern can mean different values under different encodings.

Unsigned and signed ranges

An unsigned n-bit pattern represents 0 through 2n−1. Signed encodings trade positive range for negative values. The source compares sign-and-magnitude, one’s complement, two’s complement, excess (biased) notation, and binary-coded decimal (BCD).

Ranges for n bitsUnsigned: 0 … 2n−1Sign and magnitude: −(2n−1−1) … +(2n−1−1)One’s complement: −(2n−1−1) … +(2n−1−1)Two’s complement: −2n−1 … 2n−1−1Sign-and-magnitude and one’s complement have two zero encodings. Two’s complement has one zero and one extra negative value.

Worked comparison · decode 1111 in four encodings

  1. Unsigned: 15.
  2. Sign-and-magnitude: sign bit 1 and magnitude 111, so −7.
  3. One’s complement: invert to 0000, so −0, which equals zero but has a distinct pattern.
  4. Two’s complement: the unsigned value 15 represents 15−16=−1. §3.2

What a good encoding should offer

The lecture lists the properties an integer encoding should have: one bit pattern per value, equal numbers of positive and negative values, the largest possible range, no gaps in the range, and fast, cheap arithmetic hardware. No encoding here has all of them, as this comparison for n bits shows.

Two’s complement and bias

To form −x in n-bit two’s complement, invert all n bits of x and add 1; discard a carry beyond the width. The minimum value −2n−1 is the exception: its positive counterpart is outside the signed range, so fixed-width negation leaves the same pattern and overflows. Equivalently, interpret a pattern with top bit 1 by subtracting 2n from its unsigned value. In excess-B notation, actual value = stored unsigned value − B. The lecture’s three-bit excess-4 example therefore maps 000 to −4 and 111 to 3.

Excess exists to keep numbers in order. In two’s complement a negative value starts with 1, so comparing patterns as unsigned numbers ranks every negative value above every positive one. In excess notation the all-zeros pattern is the smallest value and the all-ones pattern the largest, so the unsigned comparison gives the right order.

Decode rulesTwo’s-complement value = unsigned(pattern) − 2n when the top bit is 1Negate x: invert n bits, then add 1Excess-B value = stored value − BKeep the width fixed throughout. The same bit pattern has no signed meaning until an encoding is specified.

BCD stores decimal digits separately

In four-bit BCD, each decimal digit has its own four-bit code. For example, decimal 59 is 0101 1001 in BCD, while the ordinary binary value 59 is 00111011. BCD uses more bits but keeps each decimal digit directly readable.

A BCD digit usually takes four or eight bits. With four, only 0000–1001 are used; the six patterns 1010–1111 are not valid digits. The lecture’s number 9876510 needs 7×4=28 bits in BCD but 24 bits in ordinary binary.

Trap: do not convert all BCD bits as one binary number. Decode each four-bit group as a decimal digit.

3.3 Character data

Numbers are not the only data stored as bits. A character encoding assigns numeric codes to letters, digits, punctuation, and control characters.

ASCII and Unicode

ASCII uses seven bits, giving 128 code values. The lecture describes eight-bit extensions that use the additional 128 patterns, but those upper values depend on the particular extension. Unicode assigns code points to characters across many writing systems; its first 128 code points match ASCII. A code point and its byte encoding are related but are not the same concept. (This distinction goes beyond the notes, which do not discuss byte encodings.)

The 128 ASCII patterns divide into 52 letters (26 lowercase and 26 uppercase), 10 digits, 32 punctuation marks and 34 others: whitespace such as space, tab and return, plus control characters. The lecture’s table reads by position: bits 6–4 pick the column and bits 3–0 the row, so F, 100 0110, sits in column 100 and row 0110. Unicode aims to give every character in any language a number. The lecture says over 120,000 are defined, and the first 65,536 (the 16-bit range) cover the world’s major alphabets.

Character-code facts7-bit ASCII: 27 = 128 code valuesASCII code points: 0 … 127The first 128 Unicode code points correspond to ASCII. Byte encodings represent code points as bytes by their own rules.

Worked encoding · read a short ASCII string

The lecture’s example encodes “Fred” in hexadecimal as 46 72 65 64.

  1. Split the bytes: 46, 72, 65, 64.
  2. Read each as a hexadecimal ASCII code: 46 is F, 72 is r, 65 is e, and 64 is d.
  3. The four codes decode to “Fred”. §3.3

Trap: an encoding is a mapping, not a property of the bit pattern by itself. Identify the character set and any byte encoding before decoding text.

3.4 Unsigned binary arithmetic

Binary arithmetic follows the same place-value logic as decimal arithmetic. Carries and borrows move between columns, while the fixed bit width limits which values can be stored.

Add and subtract

Add each column and carry 1 when a column totals 2. In a subtraction, the minuend is the number subtracted from and the subtrahend is the number being subtracted: in 612−485, 612 is the minuend and 485 the subtrahend. For subtraction, borrow from a higher column when the current minuend bit is too small; a borrowed binary 1 is worth 2 in the current column. Subtraction can also be checked by adding the difference to the subtrahend.

Worked addition · include the carry

Add 1110112 and 1010102.

  1. From right to left: 1+0=1.
  2. 1+1=10, so write 0 and carry 1. Continue each column with its carry.
  3. The result is 11001012. Check: 59+42=101, and 11001012=101. §3.4

Worked subtraction · borrow across zeros

Subtract 100112 from 10001012, numbering columns from 0 at the right.

  1. Column 0: 1−1=0.
  2. Column 1: 0−1 needs a borrow. Column 2 drops from 1 to 0, and column 1 becomes 10, so 10−1=1.
  3. Columns 2 and 3: 0−0=0 each.
  4. Column 4: 0−1 needs a borrow, but column 5 is 0. Borrow from column 6, which drops to 0. Column 5 becomes 10, lends 1 and keeps 1, and column 4 becomes 10, so 10−1=1.
  5. Column 5: 1−0=1. Column 6: 0.
  6. The result is 01100102. Check: 69−19=50, and 1100102=50. §3.4

Multiply and divide

Binary multiplication uses partial products, like decimal long multiplication, but each multiplier bit is only 0 or 1. Binary division uses quotient and remainder. For divisor d>0, dividend = quotient×divisor + remainder, where 0≤remainder<divisor.

Division checkdividend = quotient × divisor + remainder0 ≤ remainder < divisorSubstitute the quotient, divisor, and remainder to check a division result.

Worked multiplication · a carry of 10

Multiply 11112 by 1112. The partial products are 1111, 11110 and 111100. Add them column by column from the right.

  1. Column 0 totals 1: write 1. Column 1 totals 2: write 0, carry 1.
  2. Column 2 holds three 1s plus the carry, total 4, or 1002. Write 0 and carry 102, which puts 2 in the next column.
  3. Column 3 totals 3+2=5: write 1, carry 2. Column 4 totals 2+2=4: write 0, carry 2.
  4. Column 5 totals 1+2=3: write 1, carry 1. Column 6 is the carry: write 1.
  5. The result is 11010012. Check: 15×7=105=64+32+8+1. §3.4

Worked long division · quotient and remainder

Divide 1101012 by 1012.

  1. The first three bits, 110, are at least 101: quotient bit 1, leaving 110−101=1.
  2. Bring down 1 to get 11, less than 101: quotient bit 0.
  3. Bring down 0 to get 110: quotient bit 1, leaving 1.
  4. Bring down 1 to get 11: quotient bit 0. No bits remain, so the remainder is 112.
  5. Quotient 10102, remainder 112. Check: 53=10×5+3 and 0≤3<5. §3.4

Memory hook: in binary addition, 1+1 writes 0 and carries 1. In subtraction, a borrow makes the current column worth 2 before subtracting. In multiplication, a column can total more than 3, so a carry can be 102.

3.5 Two’s-complement arithmetic and overflow

Two’s complement lets the same adder perform signed addition and subtraction. Correct bit operations still need a range check: a fixed-width result can wrap to a pattern with a different signed value.

Addition, subtraction, and overflow

Add the bit patterns and discard any carry beyond the most significant bit. For subtraction, negate the subtrahend and add it to the minuend. Signed overflow occurs when the exact mathematical result lies outside the representation’s range. For addition, it occurs when two operands with the same sign produce a result with the opposite sign; operands of unlike signs cannot overflow.

n-bit two’s-complement checksRange: −2n−1 … 2n−1−1A − B = A + (two’s-complement negation of B)Addition overflow: same-sign operands, opposite-sign resultSubtraction overflow: operand signs differ, result has the subtrahend’s signDiscarding carry-out is part of fixed-width addition. Carry-out alone does not signal signed overflow.

Worked example · detect overflow

Use four-bit two’s complement to calculate −7+(−6).

  1. Encode −7 as 1001 and −6 as 1010.
  2. Add: 1001+1010=1 0011. Discard the carry-out, leaving 0011.
  3. The stored result 0011 is +3, but the exact sum is −13, outside the four-bit range −8…+7. Both inputs were negative and the result is positive, so overflow occurred. §3.5

Worked example · carry-out without overflow

Use eight-bit two’s complement to calculate −2+(−5).

  1. +2 is 00000010, so −2 is 11111101+1=11111110. +5 is 00000101, so −5 is 11111010+1=11111011.
  2. Add: 11111110+11111011=1 11111001. Discard the carry-out, leaving 11111001.
  3. Decode: 249−256=−7, which is the exact sum and lies in −128…+127.
  4. A carry came out, yet there is no overflow: both inputs are negative and so is the result. §3.5

Trap: do not test a subtraction by applying the addition rule to the negated subtrahend. Take 0−(−8) in four bits: −8 negates to itself, so the sum is 0000+1000, unlike signs, which seems safe. The exact result +8 overflows. The subtraction rule catches it: the operand signs differ and the result 1000 has the subtrahend’s sign.

Multiplication and division

The lecture notes that ordinary unsigned multiplication cannot simply be applied to signed two’s-complement patterns and read at the original width. The reason: −Y is stored as 2n−Y, so unsigned multiplication gives X(2n−Y)=2nX−XY, whereas the correct 2n-bit pattern is 22n−XY. Sign-extending both operands to 2n bits and keeping the low 2n bits of the product works, but it is very inefficient. A full product may require up to twice as many bits as the operands; retain a sufficient width and interpret the result consistently. For a simple signed multiplication, multiply magnitudes and make the result negative exactly when the operand signs differ, then check the available width. The supplied slides introduce this idea but do not give a complete signed division algorithm.

Worked multiplication · −3×2 in four bits

  1. Take magnitudes: 3 is 0011 and 2 is 0010.
  2. Multiply: 3×2=6, or 0110.
  3. The signs differ, so negate: invert 0110 to 1001 and add 1, giving 1010.
  4. Check: 10−16=−6, inside −8…+7.
  5. Compare the raw patterns: 1101×0010 is 13×2=26, or 0001 1010, while −6 at eight bits is 1111 1010. Only the low four bits agree, which is why the patterns cannot simply be multiplied. §3.5

Sign check: do not treat discarded carry as overflow. Decode the fixed-width result and compare it with the exact mathematical result and allowed range.

Explain it

Answer each why or when question aloud before opening its model response.

  1. Why does the rightmost binary digit have weight 1?
  2. Why are octal and hexadecimal convenient ways to write binary?
  3. Why do sign-and-magnitude and one’s complement have two zero patterns?
  4. Why does two’s complement have one extra negative value?
  5. When is carry-out discarded, and why is that not enough to detect signed overflow?
  6. Why can BCD be easier for decimal display but less space-efficient?
Show model explanations
  1. The rightmost place is position zero, and any base raised to zero is 1. Its bit contributes either zero or one to the value.
  2. Each octal digit maps to exactly three bits and each hexadecimal digit to four. Grouping bits preserves their value while shortening the written form.
  3. Both encodings use a sign bit and a separate magnitude/complement pattern for zero. That creates distinct positive-zero and negative-zero bit patterns.
  4. With n bits, one pattern is used for zero and the remaining patterns cannot be divided evenly into equal positive and negative ranges. Two’s complement assigns the extra pattern to the negative side.
  5. Fixed-width addition retains only n result bits, so carry beyond the word is discarded. Signed overflow depends on the signs of the inputs and result, not on that discarded bit.
  6. Each four-bit BCD group can be read as one decimal digit, but four bits are used per decimal digit even when ordinary binary could represent the whole number with fewer bits.

  26. −8 negates to itself, so 0011+1000=1011, which decodes as −5. The exact result is 3−(−8)=+11, above +7, so it overflows. Subtraction rule: the operand signs differ and the result has the subtrahend’s sign. §3.5
  27. 1100 is 12, and a BCD digit stops at 9. Six patterns, 1010–1111, are unused. §3.2
  28. As unsigned numbers 3<10. In excess-8 they are −5 and 2, so the order matches. In two’s complement they are +3 and −6, so it does not. §3.2

Exam-style problems

Allow about 20 minutes per problem. State the bit width and encoding before each calculation.

1 · Compare encodings

Use four bits to represent the integer −5. Compare sign-and-magnitude, one’s complement, and two’s complement.

  1. Write the four-bit pattern in each encoding.
  2. State the range and number of zero patterns for each representation.
  3. Explain why two’s complement is useful for arithmetic despite its asymmetric range.
Show the worked answer
  1. +5 is 0101. Sign-and-magnitude is 1101. One’s complement is 1010, the inversion of 0101. Two’s complement is 1011, the inversion plus 1. §3.2
  2. For four bits, sign-and-magnitude and one’s complement both range from −7 to +7 and have two zero patterns. Two’s complement ranges from −8 to +7 and has one zero. §3.2
  3. Negation and subtraction use the same fixed-width adder: invert the subtrahend and add one. Its one extra negative value is usually a small trade-off for simpler arithmetic hardware. §3.2 §3.5

2 · Carry-out and overflow

Use four-bit two’s-complement inputs for −4 and +6.

  1. Write both input patterns and add them, showing any carry-out.
  2. Decode the retained four-bit result and compare it with the exact sum.
  3. State whether overflow occurred and explain why carry-out is not the test.
Show the worked answer
  1. +4 is 0100, so −4 is 1011+1=1100; +6 is 0110. Addition gives 1 0010, a carry-out of 1. §3.2 §3.5
  2. The retained 0010 is +2. The exact sum is also +2. §3.5
  3. No overflow: +2 lies in −8…+7, and unlike signs cannot overflow in addition. A carry came out with a correct result, so carry-out is not the signed-overflow test. §3.5

3 · From hexadecimal to a checked result

Two bytes hold C816 and 9C16.

  1. Write each byte in binary and give its unsigned decimal value.
  2. Decode each byte as eight-bit two’s complement.
  3. Add the bytes as unsigned numbers, keeping every bit.
  4. Keep eight bits of that sum, decode it as two’s complement, and decide whether the signed addition overflowed.
  5. Compute C816−9C16 by negating and adding, then test it for overflow.
Show the worked answer
  1. C8 is 1100 1000=200, and 9C is 1001 1100=156. §3.1
  2. 200−256=−56, and 156−256=−100. §3.2
  3. 200+156=356=1 011001002. §3.4
  4. The kept 01100100 is +100. The exact sum −156 is outside −128…+127, and two negatives gave a positive result, so it overflowed. §3.5
  5. Negating 10011100 gives 01100011+1=01100100. Then 11001000+01100100=1 00101100, and the kept 00101100 is +44, matching −56−(−100). The operand signs are the same, so the subtraction cannot overflow; the carry-out changes nothing. §3.5

Slips in the notes

Each of these slips was checked on the rendered slide. They are transcription or wording errors, not different rules, and this guide uses the corrected form.

  • Slide 5 · “octet”: the slide calls an octal digit an octet. An octal digit is three bits; an octet is eight bits. This guide just says octal digit.
  • Slide 22 · “first 127 characters”: the slide says the first 127 Unicode characters match ASCII. ASCII has 128 codes, 0–127, as slide 20 says, so this guide says 128.
  • Slide 24 · missing minus sign in the Excess-8 row: the entry for bit pattern 0111 is printed as 1. With four-bit excess-8, the decoded value is stored value 7 minus bias 8, which equals −1. Slides 17 and 19 use that mapping.
  • Slide 39 · lost minus and wrong exponent: “X * (Y)” should read X * (−Y). “Sign extension to 22n” should read sign extension to 2n bits; 22n is the modulus, not a width.
  • Slide 40 · sign and steps: “3 in two’s complement … 1101” should say −3. The steps also conflict: they encode negatives, multiply ignoring signs, then apply a sign. Read literally, 1101×0010 gives 26, then −26, not −6. This guide multiplies the magnitudes instead (§3.5).
