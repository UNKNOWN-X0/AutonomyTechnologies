Number and Data Representation

Algorithms, Programming, and Data Representation · Module 92313 · Chapter 3

This chapter shows how bit patterns encode numbers and characters, then uses those representations to perform arithmetic. The meaning of a bit pattern depends on the encoding and the number of bits.

3.1 Number systems and positional notation

A numeral is a compact way to write a sum of place values. Binary, octal, decimal, and hexadecimal use the same positional rule with different bases.

Expand and convert

In base b, each digit di contributes dibi, where the rightmost digit has i=0. Binary digits are 0 or 1. Decimal-to-binary repeated division records remainders; read them from last to first.

Positional value(dk…d1d0)b = Σ dibi(1100010)2 = 1·26 + 1·25 + 1·21 = 98The worked binary number is 98 in decimal. Subscripts identify the base.

Worked conversion · decimal to binary

Convert 45 to binary by repeated division.

  1. 45 ÷ 2 gives quotient 22, remainder 1.
  2. 22 ÷ 2 gives quotient 11, remainder 0; then 11 gives 5 remainder 1.
  3. Continue: 5 gives 2 remainder 1; 2 gives 1 remainder 0; 1 gives 0 remainder 1.
  4. Read remainders upward: 1011012. Check: 32+8+4+1=45. §3.1

Octal and hexadecimal

Because 8=23, each octal digit corresponds to three binary digits. Because 16=24, each hexadecimal digit corresponds to four bits. Group binary digits from the right and pad the leftmost group with zeroes if needed. In hexadecimal, A–F mean 10–15.

Compact binary groups101012 = 010 101 = 258100101002 = 1001 0100 = 94161 byte = 8 bits = 2 hexadecimal digitsThe lecture uses 16-bit words and 32-bit long words as examples; the sizes named by these terms can depend on a computer architecture.

Trap: do not read a binary string as an ordinary decimal integer. Attach its base, expand it, and only then compare values.

3.2 Integer representations

A computer stores a fixed number of bits, not a plus or minus sign unless the encoding defines one. The same pattern can mean different values under different encodings.

Unsigned and signed ranges

An unsigned n-bit pattern represents 0 through 2n−1. Signed encodings trade positive range for negative values. The source compares sign-and-magnitude, one’s complement, two’s complement, excess (biased) notation, and binary-coded decimal (BCD).

Ranges for n bitsUnsigned: 0 … 2n−1Sign and magnitude: −(2n−1−1) … +(2n−1−1)One’s complement: −(2n−1−1) … +(2n−1−1)Two’s complement: −2n−1 … 2n−1−1Sign-and-magnitude and one’s complement have two zero encodings. Two’s complement has one zero and one extra negative value.

Worked comparison · decode 1111 in four encodings

  1. Unsigned: 15.
  2. Sign-and-magnitude: sign bit 1 and magnitude 111, so −7.
  3. One’s complement: invert to 0000, so −0, which equals zero but has a distinct pattern.
  4. Two’s complement: the unsigned value 15 represents 15−16=−1. §3.2

Two’s complement and bias

To form −x in n-bit two’s complement, invert all n bits of x and add 1; discard a carry beyond the width. Equivalently, interpret a pattern with top bit 1 by subtracting 2n from its unsigned value. In excess-B notation, actual value = stored unsigned value − B. The lecture’s three-bit excess-4 example therefore maps 000 to −4 and 111 to 3.

Decode rulesTwo’s-complement value = unsigned(pattern) − 2n when the top bit is 1Negate x: invert n bits, then add 1Excess-B value = stored value − BKeep the width fixed throughout. The same bit pattern has no signed meaning until an encoding is specified.

BCD stores decimal digits separately

In four-bit BCD, each decimal digit has its own four-bit code. For example, decimal 59 is 0101 1001 in BCD, while the ordinary binary value 59 is 00111011. BCD uses more bits but keeps each decimal digit directly readable.

Trap: do not convert all BCD bits as one binary number. Decode each four-bit group as a decimal digit.

3.3 Character data

Numbers are not the only data stored as bits. A character encoding assigns numeric codes to letters, digits, punctuation, and control characters.

ASCII and Unicode

ASCII uses seven bits, giving 128 code values. The lecture describes eight-bit extensions that use the additional 128 patterns, but those upper values depend on the particular extension. Unicode assigns code points to characters across many writing systems; its first 128 code points match ASCII. A code point and its byte encoding are related but are not the same concept.

Character-code facts7-bit ASCII: 27 = 128 code valuesASCII code points: 0 … 127The first 128 Unicode code points correspond to ASCII. Byte encodings represent code points as bytes by their own rules.

Worked encoding · read a short ASCII string

The lecture’s example encodes “Fred” in hexadecimal as 46 72 65 64.

  1. Split the bytes: 46, 72, 65, 64.
  2. Read each as a hexadecimal ASCII code: 46 is F, 72 is r, 65 is e, and 64 is d.
  3. The four codes decode to “Fred”. §3.3

Trap: an encoding is a mapping, not a property of the bit pattern by itself. Identify the character set and any byte encoding before decoding text.

Recall check · answer without looking

  1. How many code values are available in seven-bit ASCII?
  2. What is the relation between ASCII and the first 128 Unicode code points?
Check these answers
  1. 27=128. §3.3
  2. The Unicode code points 0–127 correspond to the ASCII characters; their byte representation depends on the encoding used. §3.3

3.4 Unsigned binary arithmetic

Binary arithmetic follows the same place-value logic as decimal arithmetic. Carries and borrows move between columns, while the fixed bit width limits which values can be stored.

Add and subtract

Add each column and carry 1 when a column totals 2. For subtraction, borrow from a higher column when the current minuend bit is too small; a borrowed binary 1 is worth 2 in the current column. Subtraction can also be checked by adding the difference to the subtrahend.

Worked addition · include the carry

Add 1110112 and 1010102.

  1. From right to left: 1+0=1.
  2. 1+1=10, so write 0 and carry 1. Continue each column with its carry.
  3. The result is 11001012. Check: 59+42=101, and 11001012=101. §3.4

Multiply and divide

Binary multiplication uses partial products, like decimal long multiplication, but each multiplier bit is only 0 or 1. Binary division uses quotient and remainder. For divisor d≠0, dividend = quotient×divisor + remainder, where 0≤remainder<divisor.

Division checkdividend = quotient × divisor + remainder0 ≤ remainder < divisorSubstitute the quotient, divisor, and remainder to check a division result.

Memory hook: in binary addition, 1+1 writes 0 and carries 1. In subtraction, a borrow makes the current column worth 2 before subtracting.

Recall check · answer without looking

  1. What bit do you write for 1+1, and what do you carry?
  2. What inequality must the remainder satisfy?
Check these answers
  1. Write 0 and carry 1 to the next column. §3.4
  2. For a positive divisor, 0≤remainder<divisor. §3.4

3.5 Two’s-complement arithmetic and overflow

Two’s complement lets the same adder perform signed addition and subtraction. Correct bit operations still need a range check: a fixed-width result can wrap to a pattern with a different signed value.

Addition, subtraction, and overflow

Add the bit patterns and discard any carry beyond the most significant bit. For subtraction, negate the subtrahend and add it to the minuend. Signed overflow occurs when the exact mathematical result lies outside the representation’s range. For addition, it occurs when two operands with the same sign produce a result with the opposite sign; operands of unlike signs cannot overflow.

n-bit two’s-complement checksRange: −2n−1 … 2n−1−1A − B = A + (two’s-complement negation of B)Same-sign addition with opposite-sign result ⇒ overflowDiscarding carry-out is part of fixed-width addition. Carry-out alone does not signal signed overflow.

Worked example · detect overflow

Use four-bit two’s complement to calculate −7+(−6).

  1. Encode −7 as 1001 and −6 as 1010.
  2. Add: 1001+1010=1 0011. Discard the carry-out, leaving 0011.
  3. The stored result 0011 is +3, but the exact sum is −13, outside the four-bit range −8…+7. Both inputs were negative and the result is positive, so overflow occurred. §3.5

Multiplication and division

The lecture notes that ordinary unsigned multiplication cannot simply be applied to signed two’s-complement patterns and read at the original width. A full product may require up to twice as many bits as the operands; retain a sufficient width and interpret the result consistently. For a simple signed multiplication, multiply magnitudes and make the result negative exactly when the operand signs differ, then check the available width. The supplied slides introduce this idea but do not give a complete signed division algorithm.

Sign check: do not treat discarded carry as overflow. Decode the fixed-width result and compare it with the exact mathematical result and allowed range.

Recall check · answer without looking

  1. How is A−B implemented in two’s-complement arithmetic?
  2. Can two’s-complement addition overflow when the operands have unlike signs?
  3. Why can a signed product need more bits than either input?
Check these answers
  1. Negate B in the chosen width, then add it to A and discard carry-out. §3.5
  2. No. Overflow in addition requires two operands with the same sign and a result of the opposite sign. §3.5
  3. The product magnitude can exceed the range of either input width; a full-width product may need up to twice as many bits. §3.5

Explain it

Answer each why or when question aloud before opening its model response.

  1. Why does the rightmost binary digit have weight 1?
  2. Why are octal and hexadecimal convenient ways to write binary?
  3. Why do sign-and-magnitude and one’s complement have two zero patterns?
  4. Why does two’s complement have one extra negative value?
  5. When is carry-out discarded, and why is that not enough to detect signed overflow?
  6. Why can BCD be easier for decimal display but less space-efficient?
Show model explanations
  1. The rightmost place is position zero, and any base raised to zero is 1. Its bit contributes either zero or one to the value.
  2. Each octal digit maps to exactly three bits and each hexadecimal digit to four. Grouping bits preserves their value while shortening the written form.
  3. Both encodings use a sign bit and a separate magnitude/complement pattern for zero. That creates distinct positive-zero and negative-zero bit patterns.
  4. With n bits, one pattern is used for zero and the remaining patterns cannot be divided evenly into equal positive and negative ranges. Two’s complement assigns the extra pattern to the negative side.
  5. Fixed-width addition retains only n result bits, so carry beyond the word is discarded. Signed overflow depends on the signs of the inputs and result, not on that discarded bit.
  6. Each four-bit BCD group can be read as one decimal digit, but four bits are used per decimal digit even when ordinary binary could represent the whole number with fewer bits.

Exam-style problems

Allow about 20 minutes per problem. State the bit width and encoding before each calculation.

1 · Compare encodings

Use four bits to represent the integer −5. Compare sign-and-magnitude, one’s complement, and two’s complement.

  1. Write the four-bit pattern in each encoding.
  2. State the range and number of zero patterns for each representation.
  3. Explain why two’s complement is useful for arithmetic despite its asymmetric range.
Show the worked answer
  1. +5 is 0101. Sign-and-magnitude is 1101. One’s complement is 1010, the inversion of 0101. Two’s complement is 1011, the inversion plus 1. §3.2
  2. For four bits, sign-and-magnitude and one’s complement both range from −7 to +7 and have two zero patterns. Two’s complement ranges from −8 to +7 and has one zero. §3.2
  3. Negation and subtraction use the same fixed-width adder: invert the subtrahend and add one. Its one extra negative value is usually a small trade-off for simpler arithmetic hardware. §3.2 §3.5

2 · Convert, calculate, and check

Use four-bit two’s-complement inputs for −5 and +3.

  1. Write both input patterns and add them, showing any carry-out.
  2. Decode the retained four-bit result and compare it with the exact sum.
  3. State whether overflow occurred and explain why carry-out is not the test.
Show the worked answer
  1. −5 is 1011 and +3 is 0011. Addition gives 1110 with no carry-out. §3.5
  2. 1110 is 14 unsigned; subtract 16 to decode −2. The exact sum is also −2. §3.2 §3.5
  3. No overflow: the exact result −2 lies in −8…+7. Carry-out is not the signed-overflow criterion; compare the signs or the exact result to the range. §3.5
