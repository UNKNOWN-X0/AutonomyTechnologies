2.1 Algorithms are finite, executable procedures

An algorithm turns a problem into steps that a person or machine can carry out. A precise procedure also makes it possible to decide whether it finishes and what output it should produce.

From declarative facts to imperative steps

Declarative knowledge states facts. Imperative knowledge describes how to do something: a sequence of actions with a flow of control and a stopping condition. An algorithm is a finite, well-defined sequence of executable instructions for a class of problems or a computation.

Algorithm checklistinput → defined instructions → outputfinite text · executable steps · finite memory · finite stepsThe slides call finite memory use dynamic finiteness and a finite number of steps halting. A procedure that never stops does not deliver its required result.

An algorithm is more specific than “find a square root”: it says how to make and check successive guesses. The procedure in the notes starts with a guess g; if g2 is close enough to x, it stops. Otherwise it replaces g with the average of g and x/g.

Worked example · follow the square-root recipe

For x = 16 and initial guess g = 3, calculate two updates.

  1. First compare 32 = 9 with 16, so continue. The next guess is (3 + 16/3)/2 ≈ 4.167.
  2. Now 4.1672 ≈ 17.36, so update again: (4.167 + 16/4.167)/2 ≈ 4.003.
  3. The next estimate is about 4.000. The procedure approaches √16 and stops when its chosen closeness test succeeds. §2.1

Trap: an iteration rule is not complete until it states what counts as close enough and what happens when that test is not met.

2.2 A stored-program computer executes instructions

A stored-program computer can carry out many different procedures because its instructions are data stored in memory. The same machine follows a different algorithm when the stored program changes.

Instructions, control flow, and architecture

A stored-program computer keeps a sequence of instructions in memory. A processor executes them using primitive operations such as arithmetic or logic, simple tests, and moving data. Tests can change which instruction runs next; execution stops when the program says it is done or reaches its stopping condition.

Machine-level viewprogram in memory → processor executes instructions → input becomes outputThe slide's architecture diagram groups processor and control logic with registers, memory, input, and output. The diagram is a simplified model; it does not specify a particular modern computer.

The lecture lists six abstract Turing-machine primitives: move right, move left, print a symbol, scan the current symbol, erase it, and halt. Modern programming languages package low-level actions into more convenient operations. The notes emphasize that a computable procedure can be expressed in different general-purpose languages, even though syntax and tools differ.

Memory hook: the algorithm is the recipe; the stored program is that recipe represented as instructions the machine can execute.

2.3 Programs have syntax, static meaning, and behavior

A computer needs instructions that are legal in its language and have a defined interpretation. Separating the kinds of errors helps explain why a program can be rejected, crash, or run while still giving the wrong answer.

Three checks on a program expression

Syntax asks whether the symbols form a legal expression. Static semantics asks whether a syntactically legal expression is meaningful under the language's rules, such as whether the operands have compatible types. Semantics is the meaning associated with an expression that passes those checks.

Examples from the slides3.2 * 5 → syntactically valid and meaningful3 + "hi" → syntactically valid, but a static semantic errorThe exact type rules depend on the language. These examples illustrate the distinction, not a specification for every language.

A syntactic error is often caught before execution. Static semantic errors may be caught by a compiler or interpreter. A semantic error can be harder: the program may stop, run forever, or return an answer different from the programmer's intention. A valid program statement has a defined machine meaning, but that meaning may not match what its author intended.

A program can contain definitions and commands. An interpreter evaluates them in a shell, or a compiler translates the program into processor instructions. Commands may be entered directly or saved in a file for the shell to read.

  2. How can a program with no syntax or static-semantic errors still fail its purpose?

Check these answers
  1. A static semantic error: the expression's pieces are legal-looking but their combination is not meaningful under the language's rules. §2.3
  2. Its behavior may differ from the programmer's intention: it can crash, fail to halt, or return an unexpected answer. §2.3
  3. An interpreter executes/evaluates instructions in a shell; a compiler translates a program into machine instructions. The slide gives this as a broad distinction. §2.3

2.4 Propositions turn logic into two-valued inputs

Boolean circuits calculate with truth values. Propositional logic gives precise rules for combining statements before those rules are translated into algebra or gates.

Statements and connectives

A proposition is a statement that is either true or false. Compound propositions use NOT, AND, and OR. In the notes' example, the umbrella output is true when it is raining or the forecast is bad.

Core connectives¬A is true exactly when A is falseA ∧ B is true exactly when both A and B are trueA ∨ B is true when at least one of A or B is trueThe OR in this lecture is inclusive: it is also true when both inputs are true.

For example, let R mean “it is raining” and W mean “the weather forecast is bad”. The umbrella decision is U = W ∨ R. If W = 0 and R = 1, then U = 1.

More complex decisions combine several operations. The lecture gives U = C' · (W + R): take an umbrella when you are not taking the car and either the forecast is bad or it is raining. Parentheses matter because the operations have different precedence.

2.5 Boolean algebra and truth tables make the rules checkable

Boolean algebra replaces long verbal propositions with symbols and gives every operation a precise meaning. Truth tables then provide a direct way to calculate an expression for every possible input.

Translate propositions into algebra

Boolean values use 1 for TRUE and 0 for FALSE. Variables stand for propositions. The supplied slides write NOT as a prime, OR as +, and AND as ·. Read the notation carefully: here + is logical OR, not ordinary arithmetic addition.

Notation and precedenceA' = NOT AA · B = A AND BA + B = A OR BNOT first · AND next · OR lastUse parentheses to make grouping explicit. For example, C' · (W + R) is different from C' · W + R. In C, logical operators are &&, ||, !; bitwise operators are &, |, ~.

Enumerate every input

A truth table lists an expression's output for every assignment of its input variables. With n Boolean variables there are 2n assignments. Two expressions are equivalent when their output columns match in every row.

Worked example · check implication

Compare A ⇒ B with A' + B.

  1. List inputs (A,B) as (0,0), (0,1), (1,0), (1,1).
  2. Evaluate A' + B: 1, 1, 0, 1.
  3. By the truth-table definition, A ⇒ B is true when A is false or B is true, so its column is also 1, 1, 0, 1.
  4. Matching outputs in every row establishes that A ⇒ B and A' + B are equivalent. §2.5

Trap: three input variables require eight rows, not six. List all assignments before calculating an output column.

2.6 Boolean laws simplify expressions

Boolean laws let you transform an expression while preserving its output. Each identity can be checked with a truth table, and the same law can simplify the design of a circuit.

Core identities

Negation, identity, and idempotence(A')' = AA · A' = 0A + A' = 1A · A = AA + A = AA · 0 = 0A · 1 = AA + 0 = AA + 1 = 1The slides use · for AND and + for OR. A and B may themselves be compound Boolean expressions.
Commutative, associative, and distributiveA · B = B · AA + B = B + A(A · B) · C = A · (B · C)(A + B) + C = A + (B + C)A · (B + C) = A · B + A · CA + (B · C) = (A + B) · (A + C)Parentheses keep the grouping visible. The two distributive laws mirror each other with AND and OR exchanged.

De Morgan's rules

Negating a compound expression changes its operation and negates each input: NOT of an OR becomes an AND of the negations, and NOT of an AND becomes an OR of the negations.

De Morgan's laws(A + B)' = A' · B'(A · B)' = A' + B'The rules generalize to more than two inputs.

Worked example · simplify a negated expression

Rewrite (A + B)' using De Morgan's law, then evaluate it when A = 0 and B = 1.

  1. Apply (A + B)' = A' · B'.
  2. Substitute the inputs: 1 · 0 = 0.
  3. The original expression is false because at least one input to the OR was true. §2.6

2.7 Logic gates implement Boolean functions

A gate is a circuit block whose output follows a Boolean rule. Algebra connects a circuit diagram to its expression and makes it possible to build several operations from a universal gate.

Read and combine gates

AND, OR, and NOT gates represent the corresponding operations. A small circle at a gate output indicates inversion, producing NAND or NOR. Follow a multi-gate circuit from its inputs toward its output, giving each intermediate signal a name.

Inverted gates and exclusive gatesNAND(A,B) = (A · B)'NOR(A,B) = (A + B)'XOR(A,B) = A' · B + A · B'XNOR(A,B) = A' · B' + A · BXOR is true when exactly one input is true. XNOR is true when both inputs agree.

NAND is a universal gate

The lecture calls a set of functions complete when combinations of those functions can generate any Boolean function. NAND alone is complete, so NOT, AND, and OR can each be assembled from NAND gates.

Worked example · translate a two-stage NAND circuit

The first NAND receives B and C and produces I. A second NAND receives A and I and produces X.

  1. Name the intermediate output: I = (B · C)'.
  2. Write the final gate: X = (A · I)' = (A · (B · C)')'.
  3. Use (P · Q)' = P' + Q': X = A' + ((B · C)')'.
  4. Apply double negation: X = A' + B · C. §2.7

Memory hook: bubbles on outputs mean “invert this result”; translate them as a prime before simplifying.

2.8 Physical circuits take time to switch

A Boolean truth table describes the stable input-output rule. Real circuits also have timing behavior because their physical components need time to change state.

From ideal logic to a real signal

The final slides contrast an ideal, instantaneous gate with real switching. They identify time delay and saturation as limits on how quickly a physical circuit can change its output. A logic diagram therefore describes function, while a timing diagram is needed to reason about when a change becomes visible.

Two useful modelsBoolean model → which stable output follows each input?Physical model → how long does the output take to reach its new state?The supplied slides introduce the distinction but do not provide numerical delay values or a timing-analysis procedure.

Trap: do not claim that a real gate changes output at exactly the same instant as its input. The lecture explicitly notes switching delay.

Exam-style problems

Set a timer for about 20 minutes per problem. Show intermediate steps and identify the rule behind each conclusion.

1 · From a recipe to an algorithm

For this practice variation on the lecture's square-root recipe, make the stopping test explicit. For positive x, start with a positive guess g, test whether |g²−x| is below a tolerance ε, stop if so, and otherwise set g to (g+x/g)/2 and repeat.

  1. Write the sequence of steps in plain language, including the control flow and stop condition.
  2. For x=16, g=3, and ε=0.01, calculate two successive guesses to three decimals and decide whether the second estimate passes the stopping test.
  3. Explain which algorithm properties are demonstrated by the finite instruction list, the tolerance test, and the repeated update. Name one additional condition needed to justify that every run halts.
Show the worked answer
  1. Set the inputs x, g, and ε. Compute |g²−x|. If it is less than ε, output g and stop; otherwise replace g with (g+x/g)/2 and repeat the test. §2.1
  2. First update: (3+16/3)/2≈4.167. Second: (4.167+16/4.167)/2≈4.003. The residual |4.003²−16| is about 0.027, so it does not yet pass ε=0.01; another update is needed. §2.1
  3. The finite list is a finite description; its defined arithmetic and comparison steps are executable; the tolerance defines a stopping test. To establish halting for every allowed input, one must show the update eventually makes the residual less than ε (and specify valid inputs such as x>0 and ε>0). §2.1

2 · Simplify and check a NAND circuit

A circuit has I=(B·C)' and X=(A·I)'. Assume Boolean inputs.

  1. Use Boolean algebra to simplify X.
  2. Complete the output values for A,B,C equal to 0,1,1 and 1,1,1.
  3. Explain why the circuit can be built using NAND gates alone and why its physical output may not change instantaneously.
Show the worked answer
  1. Substitute I: X=(A·(B·C)')'. De Morgan gives X=A'+((B·C)')'. Double negation gives X=A'+B·C. §2.6 §2.7
  2. For 0,1,1: X=1+1·1=1. For 1,1,1: X=0+1·1=1. §2.5
  3. The original circuit already uses NAND gates, and NAND is functionally complete, so any Boolean function can be built from it. Physical switching has delay and saturation limits. §2.7 §2.8
