2.1 Algorithms are finite, executable procedures

An algorithm turns a problem into steps that a person or machine can carry out. A precise procedure also makes it possible to decide whether it finishes and what output it should produce.

In plain words: an algorithm is a recipe precise enough for a machine to follow: it says what goes in, what to do at each step, and what comes out. It must also stop. “Keep improving the guess” only becomes an algorithm once it says when the guess is good enough.

From declarative facts to imperative steps

Declarative knowledge states facts. Imperative knowledge describes how to do something: a sequence of actions with a flow of control and a stopping condition. An algorithm is a finite, well-defined sequence of executable instructions for a class of problems or a computation.

Algorithm checklistinput → defined instructions → outputfinite text · executable steps · finite memory · finite stepsRead it as: “input goes through clearly defined instructions to output”, and the four checks: the text is finite, each step can be carried out, memory use stays finite, and it stops after finitely many steps.The slides call finite memory use dynamic finiteness and a finite number of steps halting. A procedure that never stops does not deliver its required result.

The slides give a tiny example: even “1 + 2 + 3 =” is an algorithm, because it fixes the steps, their order and when you are finished.

An algorithm is more specific than “find a square root”: it says how to make and check successive guesses. The procedure in the notes starts with a guess g; if g2 is close enough to x, it stops. Otherwise it replaces g with the average of g and x/g.

Worked example · follow the square-root recipe

For x = 16 and initial guess g = 3, calculate two updates.

  1. First compare 32 = 9 with 16, so continue. The next guess is (3 + 16/3)/2 ≈ 4.167.
  2. Now 4.1672 ≈ 17.36, so update again: (4.167 + 16/4.167)/2 ≈ 4.003.
  3. The next estimate is about 4.000. The procedure approaches √16 and stops when its chosen closeness test succeeds. §2.1
  4. Sanity check: 42 = 16, so the guesses are heading for the true root.

Trap: an iteration rule is not complete until it states what counts as close enough and what happens when that test is not met.

Near miss: “start at 1 and keep adding 1 until you reach the largest whole number” has finite text and steps anyone can carry out, but it never stops, because there is no largest whole number. It fails the finite-steps check, so it is not an algorithm.

2.2 A stored-program computer executes instructions

At bottom a computer does two things: it calculates and it remembers results, and it only knows what it is told. A stored-program computer can carry out many different procedures because its instructions are data stored in memory. The same machine follows a different algorithm when the stored program changes.

In plain words: a computer only calculates and remembers. A stored-program computer keeps its instructions in the same memory as its data, so loading a different program turns the same hardware into a different machine. The processor takes each instruction from memory and carries it out.

Instructions, control flow, and architecture

A fixed-program computer, such as a calculator, does one built-in job. A stored-program computer stores and executes instructions, so its job can change. It keeps a sequence of instructions in memory. A processor executes them using primitive operations such as arithmetic or logic, simple tests, and moving data. Tests can change which instruction runs next; execution stops when the program says it is done or reaches its stopping condition.

Machine-level viewprogram in memory → processor executes instructions → input becomes outputRead it as: “the program sits in memory, the processor executes its instructions one after another, and that turns the input into the output”.The slide's diagram: the CPU holds a control unit and a processor; the processor holds registers and combinational logic. Main memory, input and output sit outside the CPU, and instructions pass from memory to the control unit. It is a simplified model, not a particular modern computer.

The lecture lists six abstract Turing-machine primitives: move right, move left, print a symbol, scan the current symbol, erase it, and do nothing (halt). Modern programming languages package low-level actions into more convenient operations, and you can use abstract methods to create new primitives. A language gives you primitives; expressions are legal combinations of them; expressions and computations have values and meanings. A computable procedure can be expressed in different general-purpose languages, even though syntax and tools differ.

Memory hook: the algorithm is the recipe; the stored program is that recipe represented as instructions the machine can execute.

Near miss: a basic calculator with fixed buttons for +, −, × and ÷ calculates and remembers a result, but its procedures are built into its circuits rather than stored as instructions in memory; giving it a new procedure would mean building a new device. That is the difference a stored program makes.

2.3 Programs have syntax, static meaning, and behaviour

A computer needs instructions that are legal in its language and have a defined interpretation. Separating the kinds of errors helps explain why a program can be rejected, crash, or run while still giving the wrong answer.

In plain words: a program can go wrong at three levels. Syntax is grammar: are the symbols arranged legally? Static semantics is sense: do the legal pieces fit together, such as adding a number to a number? Semantics is meaning: what the program actually does when it runs, which may differ from what you intended.

Three checks on a program expression

Syntax asks whether the symbols form a legal expression. Static semantics asks whether a syntactically legal expression is meaningful under the language's rules, such as whether the operands have compatible types. Semantics is the meaning associated with an expression that passes those checks.

Examples from the slides"hi"5 → not syntactically valid3.2 * 5 → syntactically valid and meaningful3 + "hi" → syntactically valid, but a static semantic errorEnglish shows the same split: “cat dog boy” is not syntactically valid, and “I are hungry” is valid syntax with a static semantic error. The exact type rules depend on the language.

A syntactic error is common and easily caught. Only some languages check for static semantic errors before running, and these errors can cause unpredictable behaviour. A semantic error can be harder: the program may stop, run forever, or return an answer different from the programmer's intention. English can be ambiguous: “Flying planes can be dangerous” has two meanings. A program statement has exactly one meaning, but it may not be the one its author intended.

A program can contain definitions and commands. An interpreter evaluates them in a shell, or a compiler translates the program into processor instructions. Commands may be entered directly or saved in a file for the shell to read.

Trap: “it runs” does not mean “it is right”. A program with no syntax or static semantic errors can still give the wrong answer.

Near miss: a program meant to average three marks that computes a + b + c / 3 has legal syntax and no static semantic error, and it runs, but the division happens before the additions, so it returns the wrong value. It passes every check except doing what was meant.

2.4 Propositions turn logic into two-valued inputs

Boolean circuits calculate with truth values. Propositional logic gives precise rules for combining statements before those rules are translated into algebra or gates.

In plain words: a proposition is a statement that is either true or false, such as “it is raining”. Connectives build bigger statements from smaller ones: NOT flips the value, AND is true only when both parts are true, and OR is true when at least one is. Writing 1 for true and 0 for false turns these rules into arithmetic a circuit can do.

Statements and connectives

A proposition is a statement that is either true or false. Compound propositions use NOT, AND, and OR. In the notes' example, the umbrella output is true when it is raining or the forecast is bad.

Core connectives¬A is true exactly when A is falseA ∧ B is true exactly when both A and B are trueA ∨ B is true when at least one of A or B is trueRead it as: “not A”, “A and B”, “A or B”; this OR includes the case where both are true.The OR in this lecture is inclusive: it is also true when both inputs are true.

For example, let R mean “it is raining” and W mean “the weather forecast is bad”. The umbrella decision is U = W ∨ R. If W = 0 and R = 1, then U = 1.

More complex decisions combine several operations. The lecture gives U = C' · (W + R): take an umbrella when you are not taking the car and either the forecast is bad or it is raining. Parentheses matter because the operations have different precedence.

Near miss: in everyday speech “tea or coffee” often means one but not both, but this lecture’s OR is inclusive: A ∨ B is also true when both are true. Exclusive or is a separate operation, XOR (§2.7).

2.5 Boolean algebra and truth tables make the rules checkable

Boolean algebra replaces long verbal propositions with symbols and gives every operation a precise meaning. Truth tables then provide a direct way to calculate an expression for every possible input.

In plain words: Boolean algebra writes logic as short formulas: a prime ' for NOT, · for AND and + for OR, with 1 for true and 0 for false. A truth table checks a formula by listing every combination of inputs with the output for each; with n inputs there are 2n rows.

Translate propositions into algebra

Boolean values use 1 for TRUE and 0 for FALSE. Variables stand for propositions. The supplied slides write NOT as a prime, OR as +, and AND as ·. Read the notation carefully: here + is logical OR, not ordinary arithmetic addition.

Notation and precedenceA' = NOT AA · B = A AND BA + B = A OR BNOT first · AND next · OR lastRead it as: “A prime is not A”, “A dot B is A and B”, “A plus B is A or B”; NOT is applied first, then AND, then OR.Use parentheses to make grouping explicit. For example, C' · (W + R) is different from C' · W + R. In C, logical operators are &&, ||, !; bitwise operators are &, |, ~ (the slide labels these “Binary”; see Slips in the notes).

2.6 Boolean laws simplify expressions

Boolean laws let you transform an expression while preserving its output. Each identity can be checked with a truth table, and the same law can simplify the design of a circuit.

In plain words: Boolean laws are rewriting rules: each swaps an expression for another that gives the same output for every input, which a truth table can confirm. They shorten formulas, and a shorter formula means a circuit with fewer gates.

Core identities

Negation, identity, and idempotence(A')' = AA · A' = 0A + A' = 1A · A = AA + A = AA · 0 = 0A · 1 = AA + 0 = AA + 1 = 1Read it as: “A or not A is always 1” and “A and not A is always 0”: a statement and its opposite are never both true and never both false.The slides use · for AND and + for OR. A and B may themselves be compound Boolean expressions. (A')' = A is listed under “Negation”, and the NAND slides call it the Involution law.
Commutative, associative, and distributiveA · B = B · AA + B = B + A(A · B) · C = A · (B · C)(A + B) + C = A + (B + C)A · (B + C) = A · B + A · CA + (B · C) = (A + B) · (A + C)Parentheses keep the grouping visible. The two distributive laws mirror each other with AND and OR exchanged.

De Morgan's rules

Negating a compound expression changes its operation and negates each input: NOT of an OR becomes an AND of the negations, and NOT of an AND becomes an OR of the negations.

De Morgan's laws(A + B)' = A' · B'(A · B)' = A' + B'(A + B + C + …)' = A' · B' · C' · …(A · B · C · …)' = A' + B' + C' + …Read it as: “not (A or B) equals not A and not B”, and “not (A and B) equals not A or not B”.The rules hold for any number of inputs.

Worked example · simplify a negated expression

Rewrite (A + B)' using De Morgan's law, then evaluate it when A = 0 and B = 1.

  1. Apply (A + B)' = A' · B'.
  2. Substitute the inputs: 1 · 0 = 0.
  3. The original expression is false because at least one input to the OR was true. §2.6

Trap: De Morgan swaps the operator as well as priming each input. (A + B)' is not A' + B'.

Near miss: (A · B)' = A' · B' looks natural, but try A = 1, B = 0: the left side is (0)' = 1 and the right side is 0 · 1 = 0. De Morgan’s law also swaps the operator: (A · B)' = A' + B'.

2.7 Logic gates implement Boolean functions

A gate is a circuit block whose output follows a Boolean rule. Algebra connects a circuit diagram to its expression and makes it possible to build several operations from a universal gate.

In plain words: a logic gate is a small circuit that computes one Boolean operation; its output stands for 1 or 0 according to its inputs. A small circle on an output means the result is inverted, turning AND into NAND and OR into NOR. NAND alone can build every other gate, so it is called universal.

Read and combine gates

AND, OR, and NOT gates represent the corresponding operations. A small circle at a gate output indicates inversion, producing NAND or NOR. Follow a multi-gate circuit from its inputs toward its output, giving each intermediate signal a name.

2.8 Physical circuits take time to switch

A Boolean truth table describes the stable input-output rule. Real circuits also have timing behaviour because their physical components need time to change state.

In plain words: a truth table says which output a gate settles on, but not when. A real gate is built from physical parts that take a short time to switch, so for a moment after an input changes, the output can still show the old value.

From ideal logic to a real signal

The final slides contrast an ideal, instantaneous gate with real switching. They identify time delay and saturation as limits on how quickly a physical circuit can change its output. Slide 48 shows the output of a NOT built from NAND following a gradual curve across a time Δt rather than jumping. Real gates are built from transistors; slide 49 shows a transistor-transistor logic (TTL) NAND gate. A logic diagram therefore describes function, while a timing diagram is needed to reason about when a change becomes visible.

Two useful modelsBoolean model → which stable output follows each input?Physical model → how long does the output take to reach its new state?Read it as: the Boolean model answers “which output?”; the physical model answers “how long until the output gets there?”.The supplied slides introduce the distinction but do not provide numerical delay values or a timing-analysis procedure.

Trap: do not claim that a real gate changes output at exactly the same instant as its input. The lecture explicitly notes switching delay.

Near miss: a circuit whose truth table is exactly right can still show a wrong value for a moment: if two signals reach a gate along paths with different delays, the gate briefly sees the new value on one input and the old value on the other. Correct logic is not the same as correct timing.

  2. The stored instructions can change while the hardware remains the same; the machine follows the program it is given. A calculator cannot do this, because its job is built in. §2.2
  3. The second expression is syntactically valid but has a static semantic problem: the operands cannot be combined meaningfully under the illustrated rules. Invalid syntax, such as "hi"5, is not a legal expression at all. The first problem concerns meaning, the second form. §2.3
  4. Each variable has two possible values, so all combinations number 2 multiplied by itself n times. Every extra variable doubles the rows, because each old row appears once with 0 and once with 1. §2.5
  5. NOT, AND, and OR have a precedence order; without parentheses the expression groups differently and can produce a different output. C' · W + R means (C' · W) + R, so R = 1 gives 1 even when C = 1. With the parentheses the same input gives 0. §2.5
  6. Any Boolean function can be assembled using NAND gates alone. NOT, AND and OR can each be built from NAND, and those three express any truth table. That is the slides' meaning of a complete set. §2.7
  7. A truth table describes stable input-output values, while real gates have switching delay and saturation limits. It says where the output ends up, not when it gets there. Two circuits with the same table may differ in timing. §2.8

Exam-style problems

Set a timer for about 20 minutes per problem. Show intermediate steps and identify the rule behind each conclusion.

1 · From a recipe to an algorithm

For this practice variation on the lecture's square-root recipe, make the stopping test explicit. For positive x, start with a positive guess g, test whether |g²−x| is below a tolerance ε, stop if so, and otherwise set g to (g+x/g)/2 and repeat.

  1. Write the sequence of steps in plain language, including the control flow and stop condition.
  2. For x=25, g=4, and ε=0.01, calculate two successive guesses and decide whether the second estimate passes the stopping test. If not, does the third?
  3. Explain which algorithm properties are demonstrated by the finite instruction list, the tolerance test, and the repeated update. Name one additional condition needed to justify that every run halts.
  4. Let the proposition S mean |g²−x|<ε. Write the condition for doing another update as a Boolean expression, and state its value at the first guess of part 2.
Show the worked answer
  1. Set the inputs x, g, and ε. Compute |g²−x|. If it is less than ε, output g and stop; otherwise replace g with (g+x/g)/2 and repeat the test. §2.1
  2. First update: (4+25/4)/2=5.125. Second: (5.125+25/5.125)/2≈5.00152. Its residual is about 0.0152, above ε=0.01, so another update is needed. The third guess is about 5.0000002, with residual about 0.000002, which passes. §2.1
  3. The finite list is a finite description; its defined arithmetic and comparison steps are executable; the tolerance defines a stopping test; the repeated update is the control flow that repeats. To establish halting for every allowed input, one must show the update eventually makes the residual less than ε (and specify valid inputs such as x>0 and ε>0). §2.1
  4. Update when S' is 1. At g=4, |16−25|=9, which is not below 0.01, so S=0 and S'=1. §2.4 §2.5

2 · Simplify and check a NAND circuit

A circuit has I=(A·C)' and X=(B·I)'. Assume Boolean inputs.

  1. Use Boolean algebra to simplify X.
  2. Write the full truth table of X for A,B,C from 000 to 111.
  3. Explain why the circuit can be built using NAND gates alone and why its physical output may not change instantaneously.
Show the worked answer
  1. Substitute I: X=(B·(A·C)')'. De Morgan gives X=B'+((A·C)')'. Double negation gives X=B'+A·C. §2.6 §2.7
  2. X for 000 to 111 is 1, 1, 0, 0, 1, 1, 0, 1. X=1 whenever B=0, and for B=1 only when A=C=1. §2.5
  3. The circuit as given is two NAND gates, and NAND is functionally complete, so any Boolean function can be built from it. Physical switching has delay and saturation limits, so the output needs time to change. §2.7 §2.8
