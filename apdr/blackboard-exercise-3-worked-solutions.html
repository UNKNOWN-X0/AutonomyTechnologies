Exercise 3.1: Memory chip architecture

Connected topic: Addressing and capacity (§5.2)

3.1.1 Memory size in bits

Try first: For a 4G × 32-bit memory, find the total capacity in bits and write it as 2x.

Attempted it? Open the worked steps

3.1.1 Memory size in bits · worked solution

  1. In the notation 4G × 32 the first number counts the words and the second gives the bits in each word. In memory sizes G means 230, so 4G = 22 · 230 = 232 words.

  2. Capacity is words times bits per word:

    232 × 32 = 232 × 25 = 237 bits

    So x = 37.

  3. Check the units: words × bits/word = bits. A sketch helps: a column of 232 rows, each row 32 bits wide.

3.1.2 Word-addressable memory

Try first: Find the address width when each address selects one 32-bit word.

Attempted it? Open the worked steps

3.1.2 Word-addressable memory · worked solution

  1. Word-addressable means every 32-bit word gets its own address, so we need one address for each of the 232 words.

  2. A k-bit address can name 2k places:

    log2(232) = 32 address bits

  3. Check: 32 bits give the addresses 0 to 232 − 1, exactly one per word.

3.1.3 Byte-addressable memory

Try first: Find the address width when each address selects one byte.

Attempted it? Open the worked steps

3.1.3 Byte-addressable memory · worked solution

  1. Byte-addressable means every byte gets its own address. Each 32-bit word holds 4 bytes:

    232 words × 4 bytes = 232 × 22 = 234 bytes

  2. Naming 234 bytes takes 34 address bits.

  3. Check: two bits more than word addressing, because each word now has 22 = 4 byte addresses inside it.

3.1.4 Byte address range

Try first: Give the lowest and highest byte addresses in hexadecimal and the number of bits needed to represent them.

Attempted it? Open the worked steps

3.1.4 Byte address range · worked solution

  1. The 234 byte addresses are numbered from 0, so the highest is one less than the count.

  2. lowest = 0x000000000

    highest = 234 − 1 = 0x3FFFFFFFF

    Writing them takes 34 bits: 234 − 1 is thirty-four 1s, which is 3 followed by eight F digits in hexadecimal (2 + 8 · 4 = 34 bits).

  3. Check: the next address, 0x400000000 = 234, lies outside the memory. The leading zeros of the lowest address only pad it to the same width.

Exercise 3.2: Memory modules architecture

Connected topic: Memory chips and modules (§5.4) · Memory interleaving (§5.5)

3.2.1 Module configuration

Try first: Complete the chip and address-width specifications for a word-addressable 1G × 32-bit memory built from 256M × 4-bit chips.

Attempted it? Open the worked steps

3.2.1 Module configuration · worked solution

  1. Build the word width first. One chip delivers 4 bits per word, so 32 / 4 = 8 chips side by side form a 32-bit module. A module then holds as many words as one chip: 256M = 228.

  2. Then build the word count. The memory needs 1G = 230 words:

    modules = 230228 = 4

    chips = 4 × 8 = 32

  3. Address widths: a module has 228 words, so it needs 28 address bits; the whole memory has 230 words, so 30.

    a)RAM chips per memory module8
    b)Memory modules4
    c)RAM chips for the full memory32
    d)Address bits needed for a memory module28
    e)Address bits needed for the full memory30

  4. Check width and count separately: 8 chips × 4 bits = 32 bits per word, and 4 modules × 256M words = 1G words. The 2 extra address bits for the full memory pick one of the 4 = 22 modules.

3.2.2 Word 14 across four modules

Try first: Locate word address 14 under high-order and low-order interleaving, numbering modules from zero.

Attempted it? Open the worked steps

3.2.2 Word 14 across four modules · worked solution

  1. The memory has 4 = 22 modules, so 2 of the 30 word-address bits select a module and the other 28 select the word inside it. Word 14 is 11102, that is 0 … 0 1110 in 30 bits.

  2. High-order interleave uses the top 2 bits for the module:

    module = ⌊14 / 228⌋ = 0

    word in module = 14

    Low-order interleave uses the bottom 2 bits:

    module = 14 mod 4 = 2

    word in module = ⌊14 / 4⌋ = 3

  4. Check by rebuilding the address. High-order: module 0 starts at word 0, so its word 14 is word 14. Low-order: module 2 holds words 2, 6, 10, 14, …, and 14 is its entry number 3 (counting from 0).

3.2.3 Word 300,000,000

Try first: Find the module and local word address for word address 300,000,000 under both interleaving schemes.

Attempted it? Open the worked steps

3.2.3 Word 300,000,000 · worked solution

  1. High-order: divide by the module size 228 = 268 435 456. Low-order: divide by the number of modules, 4.

  2. a) High-order:

    300 000 000 = 1 × 268 435 456 + 31 564 544

    Module 1, word 31 564 544 in that module.

  3. b) Low-order:

    300 000 000 = 75 000 000 × 4 + 0

    Module 0, word 75 000 000 in that module.

  4. Check by rebuilding: 1 × 228 + 31 564 544 = 300 000 000, and 4 × 75 000 000 + 0 = 300 000 000.

Exercise 3.3: Byte-addressable memory modules

3.3.1 Full-memory address width

3.3.1 Full-memory address width · worked solution

  1. The memory still holds 1G words of 4 bytes, but now every byte has an address:

    1G × 4 = 230 × 22 = 232 bytes

  2. TaskSpecificationQuantity
    a)Address bits needed for the full memory32

    Chips and modules do not change: 8 chips per module, 4 modules, 32 chips.

  3. Check: 30 bits pick the word, as before, and 2 more pick the byte inside it.

3.3.2 Word 14 after byte-addressing

Try first: Locate word 14 under both interleaving schemes. The memory modules still store complete 32-bit words.

Attempted it? Open the worked steps

3.3.2 Word 14 after byte-addressing · worked solution

  1. Word 14 starts at byte address 14 × 4 = 56 = 1110002. In a 32-bit byte address the lowest 2 bits now pick the byte inside the word, and the 30 bits above them are the old word address.

  2. Each module is 32 bits wide, so it holds whole words; the module is therefore chosen from the word address, just above the 2 byte bits.

    High-order: the top 2 address bits pick the module. Word 14 is in module 0, at byte address 56 inside it (its word 14).

    Low-order: the 2 bits just above the byte offset pick the module:

    module = 14 mod 4 = 2

    word in module = ⌊14 / 4⌋ = 3, starting at byte 3 × 4 = 12 in the module

    So word 14 is in module 2, as in 3.2.2; only the addresses are now counted in bytes.

  3. Assumption. The sheet does not say which bits interleave. If instead the lowest 2 bits of the byte address picked the module, the four bytes of word 14 (addresses 56 to 59) would land in modules 0, 1, 2 and 3, each at position 14. A word would then be split across modules, which does not fit modules built as 32-bit words, so the word-address reading above is the one to use; say so in your answer.

  4. Check with a sketch: byte addresses 0 to 15 hold words 0 to 3 in modules 0 to 3, so 56 = 4 × 14 lies in the row of word 14, module 14 mod 4 = 2.

Exercise 3.4: Endianness bytes

Connected topic: Endianness and aligned access (§5.3)

3.4.1 Define endianness

Try first: State the definition of endianness in one sentence.

Attempted it? Open the worked steps

3.4.1 Define endianness · worked solution

  1. A multi-byte value occupies several byte addresses, so the system needs a rule for which byte comes first.

  2. Endianness is the order in which a multi-byte value’s bytes are stored in memory: little-endian places the least significant byte at the lowest address, while big-endian places the most significant byte there.

  3. This rule affects multi-byte values; a single-byte value has no byte-order choice.

3.4.2 Transfer between different byte orders

Try first: Explain what must happen when data moves from little-endian memory to big-endian memory.

Attempted it? Open the worked steps

3.4.2 Transfer between different byte orders · worked solution

  1. A raw byte copy preserves the sequence of bytes. The receiving system then interprets that sequence using its own byte-order rule.

  2. To preserve the numeric value, the sender and receiver must agree on a serialized byte order, or one side must reorder the bytes during transfer. If bytes are copied unchanged without conversion, a multi-byte number may be read as a different value.

  3. Single-byte text is unaffected. A robust file or network format specifies byte order rather than relying on the sender’s native layout.

3.4.3 Transfer 0x12345678 unchanged

Try first: A 32-bit integer 0x12345678 is stored little-endian and copied unchanged into big-endian memory. Find the value read there and decide whether the original can be recovered without byte-order information.

Attempted it? Open the worked steps

3.4.3 Transfer 0x12345678 unchanged · worked solution

  1. In little-endian order, the bytes at increasing addresses are 78, 56, 34, 12. The transfer keeps that sequence unchanged.

  2. A big-endian receiver treats the first byte as most significant, so it reads 0x78563412.

  3. The original value cannot be determined from those bytes alone without knowing the sender’s byte order or other format metadata: the same four bytes can represent different integers under different conventions.
