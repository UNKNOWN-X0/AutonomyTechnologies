4.1 The floating-point model

A fixed number of bits cannot represent every real number.

Floating point uses a sign, a significand, and an exponent to cover very large and very small magnitudes.

Why not just use more integer bits?

An integer of 30 decimal digits needs about 100 bits in binary, because one decimal digit carries about 3.32 bits (log21030≈100). BCD needs 30×4=120 bits, and ASCII needs 30×8=240 bits. Scientific notation avoids this cost by storing digits and scale separately.

Range and precision

For base R (the radix), a floating-point number has the form sign × significand × Rexponent.

The exponent controls scale and therefore the approximate range.

The number of significand bits controls precision, or how finely nearby values can be distinguished.

Floating-point values are finite in number, and their spacing changes with magnitude.

Scientific notation modelx = ±M × REM is the coefficient (also called the significand or mantissa), R is the base or radix, and E is the exponent. In binary floating point, R=2.

Zones of expressibility and gaps

Take a signed 3-digit coefficient and a signed 2-digit exponent. The positive expressible zone runs from +.001×10−99 to +.999×10+99, and the negative zone mirrors it. Magnitudes above the top lie in the overflow zones. Non-zero magnitudes below the bottom lie in the underflow zones.

The gap between neighbours varies. Next to .001×10−99 the neighbours are 0 and .002×10−99, so the gap is 10−102 each way. The same digits at exponent −50 are 10−53, and that value can also be written with a finer exponent. Its neighbours are .999×10−53 (gap 10−56) and .101×10−52 (gap 10−55).

Gap in one binary zoneGap in [2e, 2e+1) with p significant bits = 2e−p+1(This follows directly from the notes’ significand model; the notes only say the gap varies.) The last of the p bits has weight 2−(p−1), and the exponent scales it by 2e.

Normalisation

One value has many forms: 0.023×101=0.230×100=2.3×10−1. Hardware needs each number to have one unique form, so the coefficient is normalised to the range [1, R). In binary that range is [1, 2), so the digit before the point is always 1. For example, 1010.112×22=1.010112×25: the point moves three places left, so the exponent rises by three.

Worked example · normalise a decimal value

Write 343000 × 10−4 in normalised decimal form with 1≤M<10.

  1. Move the decimal point in 343000 five places left to make 3.43.
  2. Increase the exponent by five to preserve the value: 3.43 × 101.
  3. Check: 343000 × 10−4=34.3, and 3.43 × 101=34.3. §4.1

Trap: moving the radix point changes the exponent in the opposite direction if the represented value is to stay the same.

4.2 Binary fractions

Binary fractional place values explain both conversion and approximation.

The first bit after the binary point has weight 2−1.

Each following bit has half the previous weight.

Convert binary fractions to decimal

Binary fractional place values0.b1b2…bk = b12−1 + b22−2 + … + bk2−kEach bi is 0 or 1. A leading integer part is evaluated with non-negative powers of 2.

Worked conversion · binary fraction to decimal

Convert 0.011012 to decimal.

  1. Use the five place values: 1/2, 1/4, 1/8, 1/16, and 1/32.
  2. Keep the places where the bit is 1: 1/4 + 1/8 + 1/32.
  3. Add: 0.25+0.125+0.03125=0.40625. §4.2

Convert decimal fractions to binary

Repeatedly multiply the fractional part by 2.

At each step, the integer part is the next binary digit, and the new fractional part is carried into the next step.

Worked conversion · terminating binary fraction

Convert 0.6875 to binary.

  1. 0.6875×2=1.375, so the first bit is 1; carry 0.375.
  2. 0.375×2=0.75, so the next bit is 0; carry 0.75.
  3. 0.75×2=1.5, so the next bit is 1; carry 0.5.
  4. 0.5×2=1.0, so the next bit is 1; the fraction is now zero.
  5. Therefore 0.6875=0.10112. Check: 1/2+1/8+1/16=0.6875. §4.2

Some fractions, such as 0.1 in decimal, repeat in binary. The remainders run 0.1, 0.2, 0.4, 0.8, 0.6, 0.2, and the return to 0.2 means the bits repeat. Cutting off at 0.0001100112 gives 0.099609375, close to 0.1 but not equal.

A finite significand stores only an approximation of a repeating expansion.

Trap: a decimal fraction that looks short is not necessarily exact in binary.

4.3 Floating-point arithmetic and error

The exponent and significand must be managed during each operation.

After the exact operation, the result may need normalisation and rounding to fit the available precision.

Multiplication

Multiply normalised values(M1 × RE1)(M2 × RE2) = (M1M2) × RE1+E2Multiply the significands and add the exponents. Then normalise and round if needed.

Worked multiplication · normalise the result

Calculate (2.6×103)(5.4×10−2).

  1. Multiply significands: 2.6×5.4=14.04.
  2. Add exponents: 3+(−2)=1, giving 14.04×101.
  3. Normalise: 1.404×102=140.4. §4.3

Addition

Before adding, express both numbers with the same exponent.

Shift the significand of the value with the smaller exponent to the right by the exponent difference.

This alignment can discard low-order digits before the addition is even performed.

Align, then addN1+N2 = (M1+M2×10E2−E1)×10E1N2 is the number with the smaller exponent, so E2−E1 is negative and M2 shifts right.

Worked addition · align exponents

Use two significant decimal digits to add 4.5×103 and 6.7×102.

  1. Rewrite the second value at exponent 3: 6.7×102=0.67×103.
  2. Add significands: (4.5+0.67)×103=5.17×103.
  3. Round to two significant digits: 5.2×103. The exact sum is 5170, while this two-digit result is 5200. §4.3

Rounding, overflow, and comparison

Truncation drops extra digits and tends to bias results in one direction.

Rounding chooses a nearby representable value and usually gives a better approximation.

Worked comparison · truncate or round

With a 2-digit coefficient, store (2.3×101)(2.3×101).

  1. Multiply: 2.3×2.3=5.29, and 1+1=2, giving 5.29×102, which needs three digits.
  2. Truncate: 5.2×102. The error is 9, and truncation always errs low for positive values, so the error is biased.
  3. Round: 5.3×102. The error is only 1, and rounding errs either way, so it is unbiased. §4.3

Exponent overflow occurs when the result is too large for the format.

Exponent underflow occurs when the result is too small for the normalised range.

The slides describe infinity or an exception for overflow, and zero or an exception for underflow in their simplified model.

IEEE formats also provide denormalised numbers near zero.

For approximate comparisons, choose a tolerance ε that fits the scale and precision of the problem.

Absolute tolerance exampleTreat a as close to b when |a−b|<εFor b=1 and ε=0.000005: 0.999995<a<1.000005A fixed absolute tolerance may be unsuitable when magnitudes vary greatly. The slides also introduce relative closeness.

Sign check: estimate the order of magnitude before accepting a rounded result.

4.4 IEEE 754 binary formats

A shared format defines how floating-point fields are stored and how arithmetic behaves.

The slides introduce IEEE 754 as a widely adopted standard for predictable binary floating-point arithmetic.

Single and double precision

FormatTotalSignExponentFraction fieldSignificand precisionBias
Single32 bits1 bit8 bits23 bits24 bits for normal values127
Double64 bits1 bit11 bits52 bits53 bits for normal values1023

For a normalised binary value, the leading significand bit is 1 and is omitted from the stored fraction field.

The coefficient is called the significand in the standard. Single precision gives about 7 decimal digits of precision and normalised ranges of roughly ±10−38 to ±1038. Double precision gives about 16 digits and roughly ±10−308 to ±10308. The notes reserve single precision for when memory is scarce, or for debugging numerical work, because rounding errors show up sooner.

The exponent field stores an excess (biased) value rather than a two’s-complement exponent. This lets non-negative floats be compared with simple integer comparisons.

Normalised value rulevalue = (−1)S × 1.F × 2E−biasSingle bias = 127; double bias = 1023S is the sign bit, E is the unsigned exponent field, and F is the stored fraction interpreted after the binary point. This rule is for normalised values.

Convert decimal to single precision

Worked conversion · 42.6875

  1. Convert to binary: 42.6875=101010.10112.
  2. Normalise: 1.010101011×25, so the sign bit is 0.
  3. Store the fraction after the hidden leading 1: 01010101100000000000000.
  4. Bias the exponent: 5+127=132=100001002.
  5. The fields are 0 | 10000100 | 01010101100000000000000, or hexadecimal 422A C000. §4.4

Decode single precision

Worked decoding · BEC0 0000

  1. The sign bit is 1, so the value is negative.
  2. The exponent field is 011111012=125; subtract the bias: 125−127=−2.
  3. Restore the hidden bit: 1.1000…2=1.5.
  4. Scale: 1.5×2−2=0.375. Apply the sign: −0.375. §4.4

Add in single precision

Worked addition · 42.6875 + 0.375

  1. Read the fields: 42.6875 has exponent field 132 and 0.375 has 125. Restore the hidden bits: 1.0101010112 and 1.12.
  2. The exponents differ by 132−125=7, so shift the smaller significand 7 places right: 1.12 becomes 0.000000112.
  3. Add: 1.010101011+0.00000011=1.0101100012, at exponent 5.
  4. Check: 1.0101100012×25=101011.00012=43.0625, which is 42.6875+0.375.
  5. The fields are 0 | 10000100 | 01011000100000000000000, or hexadecimal 422C 4000. §4.4

Trap: restore the hidden leading 1 when decoding a normalised value, but do not apply that rule to a denormalised value.

4.5 Zero, denormalised numbers, infinity, and NaN

Reserved exponent patterns extend useful behaviour beyond normalised values.

IEEE formats encode five kinds of value: zero, normalised numbers, denormalised numbers, infinity and NaN. In single precision, exponent field zero and exponent field all ones have special interpretations, so normalised exponents run from −126 to 127 rather than −127 to 128.

Exponent fieldFraction fieldMeaningTrue exponent
All zeroesAll zeroesPositive or negative zero—
All zeroesNon-zeroDenormalised (subnormal) number−126
Neither all zeroes nor all onesAny patternNormalised number−126 to 127
All onesAll zeroesPositive or negative infinity—
All onesNon-zeroNaN, or not-a-number—

For a denormalised single-precision number, the leading bit is 0 and the effective exponent is −126.

Denormalised values provide a gradual step from the smallest normalised values toward zero.

Infinity represents overflow results and divisions of non-zero values by zero. You can do basic arithmetic with it, such as ∞+5=∞.

NaN represents an operation without a real-number result, such as 0/0, infinity−infinity, 0×∞, or the square root of a negative number.

Operations on infinity and NaN follow format rules, not ordinary real-number algebra in every case.

  2. Why can two nearby real values have different spacing when stored at different magnitudes?
  3. Why does 0.1 decimal not have a finite binary fraction?

Show model explanations
  1. The exponent scales a significand by powers of the base, expanding which magnitudes can be represented. Precision depends chiefly on how many significand bits distinguish values at a given scale.
  2. At a larger exponent, the same significand step is multiplied by a larger power of 2. Therefore adjacent representable values are farther apart.
  3. A finite binary fraction has a denominator that is a power of 2 after reduction. One tenth has a factor of 5 in its denominator, so its binary expansion repeats.
  4. Only values with the same exponent have significands describing the same scale. Alignment expresses both at a shared scale before combining them.
  5. Alignment shifts the smaller significand to the right. If the exponent difference is large, its significant bits may fall beyond the available precision.
  6. Every normalised binary number begins with 1 before the point, so the format can infer that bit and use its storage for another fraction bit.
  7. A denormalised represents a non-zero value smaller than the minimum normalised magnitude, close to zero.
  8. Absolute or relative error that is acceptable depends on the scale and purpose of the calculation. One fixed tolerance may be too strict for large values or too loose for small ones.

  3. Compare the rounded result with the exact decimal sum and explain the source of the difference.
  4. Carry the same alignment into single precision: add 13.25 and 0.375, and give the fields of the sum.
Show the worked answer
  1. 5.6×102=0.056×104. §4.3
  2. (3.4+0.056)×104=3.456×104, which rounds to 3.5×104. §4.3
  3. The exact sum is 34560 and the rounded result is 35000. The smaller addend contributes digits beyond the two-digit precision, so rounding changes the stored result. §4.3
  4. 13.25=1.101012×23 and 0.375=1.12×2−2. The exponents differ by 5, so 1.12 becomes 0.0000112. The sum is 1.1011012×23=13.625. The fields are 0 | 10000010 | 10110100000000000000000. §4.4

Slips in the notes

Each item was checked on the rendered slide. The guide uses the corrected form; numbers are PDF slide numbers.

  • Slide 3 · light year: printed as 9,130,000,000,000 km. The accepted value is about 9.46×1012 km.
  • Slide 3 · solar mass: printed as 2 followed by nine groups of 000, which is 2×1027 kg. The accepted value is about 2×1030 kg.
  • Slide 3 · electron diameter: printed as 10−20 m. This is probably only illustrative, because an electron has no established diameter. The guide does not use it.
  • Slide 40 · single-precision range endpoints are reversed: it prints 1038 to 10−38 for the positive range. In increasing order the range is approximately 10−38 to 1038, and the negative range is −1038 to −10−38 as printed.
  • Slide 42 · double-precision range endpoints are reversed: it prints 10308 to 10−308 for the positive range. In increasing order the range is approximately 10−308 to 10308.
  • Slide 49 · signalling NaN (simplified): it presents a signalling NaN as the outcome of an operation that raises an exception. In IEEE 754 a signalling NaN is an encoding that raises the exception when it is used. Learn the slide’s wording, but know that it is a simplification.
  • Slides 41 and 47–48 · notation clash, not an error: slide 41 lists −127 and 128 as excess values, but those two patterns are reserved. Slide 48 reconciles this: the normalised range is −126 to 127.
  • Slides 40 and 42 · notation clash, not an error: F is labelled “Significand”, but it holds only the stored bits after the hidden 1. The guide calls F the fraction field.

The decimal ranges are rough magnitudes, not exact endpoint values.
